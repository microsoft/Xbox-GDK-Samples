# DevkitToolLauncher サンプル

*このサンプルは、Microsoft Game Development Kit と互換性があります (2022 年 3 月)*

# 説明

Xbox 開発キット マシンは、ゲーム タイトルの実行やテスト以外にも利用できる強力なハードウェアです。 Xbox Game Core アプリケーションは、開発キットの完全な処理リソースのロックを解除し、API の使用をWINAPI_FAMILY_GAMESサブセットに制限する Win32 アプリケーションを実行できます。

DevkitToolLauncher サンプルは、ツール目的で開発キットのタイトル パーティションでプロセスを実行しやすくする Xbox アプリケーションを提供します。 さらに、Win32 本体の CPU のみのプロセスと Xbox D3D12 GPU プロセスの両方を使用する方法を示すために、2 つのサンプル プロセスが用意されています。

# サンプルの構築

Xbox One 開発キットを使用している場合は、アクティブなソリューション プラットフォームを `Gaming.Xbox.XboxOne.x64` に設定します。

Project Scarlett を使用している場合は、アクティブなソリューション プラットフォームを `Gaming.Xbox.Scarlett.x64` に設定します。

*詳細については、* *GDK ドキュメント*の「__サンプルの実行__」を参照してください。

また、ビルド、デプロイ、実行など、サンプルのコマンドライン使用を容易にするために、いくつかのスクリプトも提供されています。 スクリプトを使用するには、"*Xbox \[One/Scarlett\] VS \[2017/2019\] ゲーム コマンド プロンプト*" を開き、サンプル ディレクトリに移動します。 スクリプトについては、次の表で説明します:

| スクリプト | 使用法 |
|---|---|
| Build.bat | Build.bat \[構成\] \[Platform\]<br /><br />指定した Configuration(Debug, Release) および Platform(XboxOne, Scarlett) の DevkitToolLauncher.exe、CPUTool.exe、GPUTool.exe をビルドします。 CPUTool.exe は、常に単純なコンソール Win32 アプリケーションとして x64 構成を使用して構築されます。 |
| Deploy.bat | Deploy.bat \[Platform\]<br /><br />以前にビルドされた DevkitToolLauncher.exethat のルース ビルドを既定の開発キットにデプロイします。 |
| DeployExampleTools.bat | DeployExampleTools.bat \[Configuration\]\[Platform\]<br /><br />CPUTool.exe と GPUTool.exe を既定の開発キットのSystemScratch ドライブにコピーします。 これらのアプリケーションは、"d:\\DevkitToolLauncherExampleTools\\\[CPU/GPU\]Tool" フォルダーにデプロイされます。 |
| BuildAndDeploy.bat | BuildAndDeploy.bat \[Configuration\] \[Platform\]<br /><br />Build.bat、Deploy.bat、DeployExampleTools.bat を 1 つのスクリプトに結合します。 |
| Run.bat | Run.bat \[CommandLine\]<br /><br />以前にデプロイされたDevkitToolLauncher.exe を起動し、スクリプトのすべてのパラメーターをDevkitToolLauncher.exe のコマンド ラインに渡します。 コマンド ライン パラメーターの[使用方法の詳細については、以下の「コマンド ラインの使用法](#Command_Line_Usage)」セクションを参照してください。 |

# サンプルの使用方法

このサンプルには、DevkitToolLauncher.exe、CPUTool.exe、GPUTool.exe の 3 つのプロセスが用意されています。 DevkitToolLauncher.exe は主要なサンプル プロセスであり、他の 2 つのプロセスは、DevkitToolLauncher.exe で実行できる CPU のみのプロセスと GPU を利用するプロセスの例として提供されます。

## サンプル機能

DevkitToolLauncher プロセスは、ツール ブラウザー、起動設定、ランタイム ログの 3 つの画面に分割されます。 さまざまな画面では、実行するプロセスを見つけ、そのプロセスのスタートアップ情報を設定し、実行中のプロセスのコンソール出力を表示できます。

### ツール ブラウザー

![説明は自動で生成されたものです](./media/image3.png)

ツール ブラウザーは、開発キットのシステム スクラッチ ドライブ (d:\\) を介してファイル ブラウザー インターフェイスを提供します。 このブラウザーを使用すると、実行可能ファイルに移動して実行し、選択できます。 実行可能ファイルを選択すると、サンプルは *[起動の設定]* 画面に進みます。

### 設定を開く

![グラフィカル ユーザー インターフェイス、テキスト、自動生成された説明](./media/image4.png)

*[起動の設定]* 画面では、選択したツール実行可能ファイルの起動動作を設定できます。 この画面を使用すると、コマンド ライン パラメーター、作業ディレクトリ、およびサンプルを GPU サポートの有無にかかわらず起動するかどうかを設定できます。

テキスト入力のいずれかを選択すると、スクリーン キーボードが表示され、パラメーターが入力されます。 コマンド ライン パラメーターと作業ディレクトリは、"DevkitToolLauncherParameterCache.json" というシステム スクラッチ ドライブのルートにあるキャッシュ ファイルに保存されます。 このキャッシュを削除して、保存されたパラメーターをリセットできます。

GPU 機能を備えるツールをサポートするために、*[起動 (CPU と GPU)]* ボタンは、ツールを起動する前にサンプルのレンダリングを中断します。 ツール実行可能ファイルが終了または終了すると、レンダリングは自動的に再びスピンアップされます。 このサンプルで GPU プロセスをサポートする方法の詳細については、「[Xbox 開発キットの GPU プロセス](#_Hlk70930525)」セクションを参照してください。

*[起動 (CPU のみ)]* を選択すると、レンダリングを中断せずに *[ランタイム ログ]* 画面に進みます。

選択したツール実行可能ファイルに GPU 機能があり、*[起動 (CPU のみ)]* が選択されている場合、GPU を使用しようとしている 2 つのプロセスの結果として、本体で未定義の動作上の問題が発生します。 たとえば、アプリケーションがクラッシュしたり、画面にアーティファクトが表示されたり、本体がシャットダウンされたりすることがあります。 詳細については、「[Xbox 開発キットの GPU プロセス](#_Hlk70930525)」を参照してください。

実行中のツール実行可能ファイルで要求されていない受信接続を許可する必要がある場合は、MicrosoftGame.config ファイルを使用してそれらのポートを開く必要があります。 詳細については、「[ポートと Xbox ファイアウォール](#Ports_Firewall)」を参照してください。

### ランタイム ログ

![説明は自動で生成されたものです](./media/image5.png)

[ランタイム ログ] 画面は、*[起動の設定]* 画面で起動オプションのいずれかを選択したときに表示される最後の画面です。

この画面では、選択した実行可能ファイルをサブプロセスとして起動し、その StdOut と StdErr の書き込みを DevkitToolLauncher プロセスにパイプ処理します。 これらのパイプ出力が画面に表示されます。 ゲームパッドを使用して、画面上のログを移動できます。

ツール サブプロセスで GPU が使用され、レンダリングが *[起動の設定]* 画面の *[起動 (CPU と GPU)]* ボタンを介して中断された場合、この画面は表示されません。 ただし、サンプルはまだ出力をパイプ処理し、実行中のプロセスを管理しています。 ツール サブプロセスが終了すると、この画面が自動的に表示され、発生したすべてのログが表示されます。

レンダリングが中断されたかどうかにかかわらず、ゲームパッドで \[B\] を保持することで、ツール サブプロセスをいつでも終了できます。 ツール サブプロセスが実行されなくなったら、\[B\] キーを押して *[ツール ブラウザー]* 画面を返し、最初からやり直すことができます。

## コマンド ラインの使用方法

指定されたスクリプトやコマンド ラインを使用してサンプルを使用する必要はありません。 ただし、DevkitToolLauncher サンプルを使用してコマンド ラインを使用してツールを起動する方法を示すために提供されました。

まず、いずれかの Xbox ゲーム コマンド プロンプトを開きます。 次に、*"cd /D \[SamplePath\]"* コマンドを使用してサンプル ディレクトリに移動します。

### ビルド

ビルドは、サンプルのディレクトリに用意されている Build.bat スクリプトを使用して実行できます。 コマンド ライン パラメーターは次のとおりです:

```
Build.bat [Configuration] [Platform]
```


たとえば、Scarlett 用にビルドするには、コマンド *"build.bat release scarlett"* を使用します。

### 配置

デプロイするために、Deploy.bat という別のスクリプトが提供されています。 DevkitToolLauncher サンプルをデプロイすると、内部的に *"xbapp deploy"* コマンドを使用して、ルース ビルドを開発キットにコピーします。

```
Deploy.bat [Platform]
```


GPUTool と CPUTool をデプロイするには、DeployExampleTools.bat スクリプトを使用します。 このスクリプトは、これらのサンプル ツールを "DevkitToolLauncherExampleTools" という名前のフォルダー内の SystemScratch ドライブにコピーします。 これらのツールは、サンプルのメイン インストール フォルダー内ではなく、サンプルの *[ツール ブラウザー]* 画面で検出できるように SystemScratch ドライブに展開されます。

```
DeployExampleTools.bat [Configuration] [Platform]
```


### 1 ステップでのビルドとデプロイ

BuildAndDeploy.bat スクリプトは、わかりやすくするために、上記の 3 つのスクリプトを 1 つのスクリプトに結合します。

BuildAndDeploy.bat \[Configuration\] \[Platform\]

### Running

DevkitToolLauncher.exe には、*[ツール ブラウザー]* と *[設定の起動]* 画面のスキップ、ツール プロセスの起動、*[ランタイム ログ]* 画面への直接移動を許可するコマンド ラインセットアップが含まれています。 コマンド ライン セットアップは次のとおりです:

DevkitToolLauncher.exe \[-gpu/processUsesGpu\] \[-workingDir \"path\"\] \[\-- \"process\" \[commandline\]\]

このコマンド ラインを使用すると、*[設定の起動]* 画面で設定できるのと同じ情報を設定できます。

| パラメーター | 説明 |
|---|---|
| -gpu または - processUsesGpu | 省略可能。 指定した場合、DevkitToolLauncher.exe サンプルは、サブプロセスの間、レンダリングを中断します。 |
| -workingDir | 実行するプロセスを指定する場合は必須です。 サブプロセスに設定する作業ディレクトリを指定します。 |
| \-- | 省略可能。 "\--\" トークンがコマンド ラインに表示される場合、サンプルは次のパラメーターを実行するサブプロセスとして解釈します。 サブプロセスは、プロセスへの完全なパスである必要があります。 プロセスの後のすべてのパラメーターは、そのサブプロセスのコマンド ラインとして渡されます。 |

たとえば、DeployExampleToole.bat を使用してシステム スクラッチ ドライブにコピーされた CPUTool の例を 5 秒間実行するには、次のコマンドを使用します:

```
Run.bat -workingDir "d:\DevkitToolLauncherExampleTools\CPUTool" --"d:\DevkitToolLauncherExampleTools\CPUTool\CPUTool.exe" 5
```


レンダリングを含む GPUTool の例を実行するには、次のコマンドを使用します:

```
Run.bat -gpu -workingDir "d:\DevkitToolLauncherExampleTools\GPUTool"
-- "d:\DevkitToolLauncherExampleTools\GPUTool\GPUTool.exe"
```


注: GPUTool.exe プロセスは、画面上に三角形をレンダリングし、自動的に終了しません。 ゲームパッドで \[B\] を保持することで、GPUTool.exe を終了できます (DevkitToolLauncher.exe によって起動された場合)。

### タイトルを

Run.bat コマンド ラインは、*xbapp* を使用して DevkitToolLauncher サンプルを開始し、コマンド ラインを渡します。 コマンド ラインからサンプルを終了する場合は、*"xbapp terminate"* を実行できます。

## 独自のツール

DevkitToolLauncher サンプルは、独自のツールを実行するための完全なホスティング オファリングと、そのような場合に開発キットを使用する方法に関する教育リソースを目的としています。 独自のツールを使用している場合や、いくつかのツールの作成を計画している場合は、上記の Run.bat の手順を使用してそれらをホストできます。

ツールとして実行できるコンソール アプリケーションの詳細については、「[Xbox 開発キットの Win32 アプリケーション](#Win32_Info)」を参照してください。 開発キットの GPU を利用できるツールの詳細については、「[Xbox 開発キットの GPU プロセス](#_Hlk70930525)」を参照してください。

DevkitToolLauncher でホストできるようにするには、開発キットのシステム スクラッチ ドライブにツールを配置する必要があります。 これを行うには、"*xbcp.exe*" ツールを使用します。

```
xbcp [ToolLocationPathOnLocalPC] xd:\[Folder]
```


# 実装メモ

このサンプルでは、Xbox タイトルでは一般的ではないいくつかの機能を使用します。 さらに、開発キットで予期しないエラーが発生しないようにするために考慮する必要がある特別な要件があります。 以下の各セクションでは、開発キットでツールを実行するためのさまざまな機能、要件、およびその他の考慮事項について説明します。

## Xbox タイトル パーティション

Xbox 開発キットで実行されているアプリケーションがハードウェア リソースにフル アクセスできるようにするには、タイトル パーティション内で実行する必要があります。 タイトル パーティションは、特にこの目的のために Xbox 本体上の仮想マシンです。

通常、Xbox のタイトルは開発キットに展開されるか、パッケージとしてインストールされ、システムへの登録が発生します。 その後、Xbox システムはタイトル パーティションでこれらのタイトルを適切に起動できます。

システムに登録されていないツールまたはその他のスタンドアロン プロセスがある場合でも、タイトル パーティションでこれらを実行できます。 ただし、最初にタイトル パーティションをアクティブにする必要があります。 DevkitToolLauncher アプリケーションでは、DevkitToolLauncher.exe の起動時にタイトル パーティションがアクティブであることがシステムによって保証されるため、この処理が行われます。 次に、DevkitToolLauncher は でツールまたはプロセスを起動します。
[CreateProcess](https://docs.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-createprocessa)
これはタイトル パーティション内にあり、完全なハードウェア リソース アクセス権を持ちます。

注: *xbrun.exe* ツールは、タイトル パーティションでアプリケーションを起動することもできます。 ただし、*xbrun.exe* では、タイトル パーティションが最初にアクティブであるとは保証されません。 タイトルが Xbox 開発キットで現在実行されている場合は、*xbrun.exe* の *"/x/title"* パラメーターで、実行可能ファイルをタイトル パーティションで実行するように指定しました。 *xbrun.exe* の詳細については、GDK ドキュメントを参照してください。

## ポートと Xbox ファイアウォール

Xbox 本体と Xbox 開発キットには、TCP と UDP の両方に対して、既定でほとんどの未承諾の受信接続要求を防ぐファイアウォールがあります。 リテール タイトルの場合、未承諾の受信 TCP は常にブロックされ、これを回避する方法はありません。 ただし、UDP は、*XNetworkingQueryPreferredLocalUDPMultiplayerPort\[Async\]* を使用して照会できる優先ローカル UDP マルチプレート ポートを使用できます。

Xbox 開発キットは、MicrosoftGame.config ファイルのエントリを介して、未承諾の受信 TCP パケットと UDP パケットを許可するように構成できます。

```
<?xml version="1.0" encoding="utf-8"?>
<Game configVersion="0">
...
  <DevelopmentOnly>
    <DebugNetworkPortList>
      <DebugNetworkPort>4600</DebugNetworkPort>
      <DebugNetworkPort>4601</DebugNetworkPort>
    </DebugNetworkPortList>
  </DevelopmentOnly>
</Game>
```


要求されていない受信接続を許可するポートごとに、別の *DebugNetworkPort* エントリを *DebugNetworkPortList* に追加する必要があります。 これは、TCP 経由で直接相互に通信する P2P ツールなどの場合に必要です。

MicrosoftGame.config ファイルが更新されたら、タイトルを更新時にピックアップするように再デプロイする必要があります。 DevkitToolLauncher サンプルに対してこれを行う簡単な方法は、*BuildAndDeploy.bat* スクリプトをもう一度実行することです。

## Xbox 開発キットの Win32 アプリケーション

タイトル パーティションでは、特定の Xbox 統合を行っていない Win32 コンソール アプリケーションを直接実行できます。 ただし、Win32 API の可用性は、Windows PC で通常使用できるものの除去されたサブセットです。

Win32 アプリケーションを使用可能な API のみに制限するには、Windows ヘッダーを含める前に *WINAPI_FAMILY* を *WINAPI_FAMILY_GAME* に定義する必要があります。

```
#define WINAPI_FAMILY WINAPI_FAMILY_GAMES
#include <Wwindows.h>
```


CPUTool プロジェクトは、この非常に単純な例です。 *WINAPI_FAMILY_GAMES* に制限されたコンソール Win32 アプリケーションをビルドします。 結果として、CPUTool.exe は Windows PC と Xbox 本体の両方で正常に実行できます。

注: これらのアプリケーションはコンソール アプリケーションのみで、レンダリング ライブラリは使用しないでください。 レンダリングでは、次のセクションで説明する Xbox D3D12 を使用できます。

## Xbox 開発キット上の GPU プロセス

タイトル パーティションで実行されているプロセスでは、D3D GPU の使用に関するより大きい制限があります。

* 一度に Direct3D を利用できるのは、タイトル パーティション内の 1 つのプロセスのみです。
* Xbox 固有の D3D12 デバイス メソッド *SuspendX/ResumeX* を使用して、D3D を利用する複数のプロセスを管理できます。 2 つのプロセスで D3D を同時にアクティブに利用することはできません。
* Xbox 固有の D3D ヘッダーとライブラリを使用する必要があります。

これらの考慮事項を不適切に処理すると、アプリケーションがクラッシュしたり、レンダリングが破損したり、本体がクラッシュしたりする可能性があります。 DevkitToolLauncher サンプルでは、GPU を利用するサブプロセスを作成する前に *SuspendX* を使用してこれらのケースを処理します。 そのサブプロセスが完全に終了すると、*ResumeX* を使用してサンプルのレンダリングが再度有効になります。

GPUTool プロジェクトは、画面上に三角形をレンダリングする単純なプロセスです。 これは、GPU に関する考慮事項が考慮されている場合に、タイトル パーティションで GPU サブプロセスを使用する方法を示すために使用されます。

## 複数のプロセスを含む GameInput

現在 (このサンプルの作成時に) GameInput ライブラリは、このサンプルの作成時に一度に 1 つ以上のプロセスで使用することはサポートされていません。 また、プロセス内でクリーンアップして再初期化したり、プロセスを終了して開始したりすることはできません。 その結果、GameInput を初期化する最初のプロセスが、それを使用できる唯一のプロセスです。 初期化を試みる将来のプロセスはクラッシュします。

DevkitToolLauncher サンプルでは、GameInput を使用して入力処理を提供するため、ツール サブプロセスは現在 GameInput を利用できません。

## CPU 使用率のオーバーヘッドのサンプル

一般に、DevkitToolLauncher サンプルの CPU オーバーヘッドは非常に低くなります。 [スリープ状態](https://docs.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-sleep)でフレーム レートを 30FPS に制限することで、使用率を低く抑えます。 スリープ状態でない場合のサンプル機能のほとんどは、非常に迅速です。 ただし、ツール サブプロセスですべての CPU コアの処理時間をできるだけ長くする必要がある場合は、デバッグ構成での UITK のレンダリングが問題になる可能性があります。

デバッグ構成で最適なツール サブプロセス パフォーマンスを得るには、GPU 以外のプロセスを含む任意のプロセスで *[起動 (CPU と GPU)]* (またはコマンド ラインを使用する場合は -gpu) を使用できます。 これによりサンプルレンダリングが中断されるため、DevkitToolLauncher サンプルのオーバーヘッドはほとんど削除されます。

リリース構成を使用してビルドすると、UITK のパフォーマンスへの影響も効果的に削除されます。
