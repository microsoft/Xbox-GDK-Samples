# DevkitTooling サンプル

*このサンプルは、Microsoft Game Development Kit と互換性があります (2022 年 3 月)*

# 説明

Xbox 開発キット マシンは、ゲーム タイトルの実行やテスト以外にも利用できる強力なハードウェアです。 Xbox Game Core アプリケーションは、開発キットの完全な処理リソースのロックを解除し、API の使用をWINAPI_FAMILY_GAMESサブセットに制限する Win32 アプリケーションを実行できます。

DevkitTooling サンプルは、Xbox Devkits でツールとして実行できる形で CPU と GPU サブプロセスを起動する方法を示すものです。

# サンプルのビルド

Xbox One 開発キットを使用している場合は、アクティブなソリューション プラットフォームを `Gaming.Xbox.XboxOne.x64` に設定します。

Project Scarlett を使用している場合は、アクティブなソリューション プラットフォームを `Gaming.Xbox.Scarlett.x64` に設定します。

*詳細については、**GDK ドキュメント*の「__サンプルの実行__」 を参照してください。

# サンプルの使用方法

DevkitTooling サンプルでは、サブプロセスとして実行されたツールからのログ出力を表示する 1 つの画面が開かれます。

![説明は自動で生成されたものです](./media/image3.png)

CPU ツール サブプロセスの例を開始するには、ゲーム パッドの \[X\] を押します。 GPU ツール サブプロセスの例を開始するには、ゲーム パッドの \[Y\] を押します。 サブプロセスの例は、合計 5 秒間実行された後、自動的に終了します。 サブプロセスのログ出力が画面に表示されます。

GPU ツール サブプロセスを実行すると画面が切り替わり、このサンプルではなく、ツールのレンダリング (単純な三角形) が表示されます。 GPU ツールが終了すると、サンプルのレンダリングが再開されます。 この動作をサポートするためのレンダリングの中断は *SuspendX*、再開は *ResumeX* で行われています。 詳細については、実装メモを参照してください。

![自動生成された図形の説明](./media/image4.png)

# 実装メモ

このサンプルでは、Xbox タイトルでは一般的ではないいくつかの機能を使用します。 さらに、開発キットで予期しないエラーが発生しないようにするために考慮する必要がある特別な要件があります。 以下の各セクションでは、開発キットでツールを実行するためのさまざまな機能、要件、およびその他の考慮事項について説明します。

## Xbox タイトル パーティション

Xbox 開発キットで実行されているアプリケーションがハードウェア リソースにフル アクセスできるようにするには、タイトル パーティション内で実行する必要があります。 タイトル パーティションは、特にこの目的のために Xbox 本体上の仮想マシンです。

通常、Xbox のタイトルは開発キットに展開されるか、パッケージとしてインストールされ、システムへの登録が発生します。 その後、Xbox システムはタイトル パーティションでこれらのタイトルを適切に起動できます。

システムに登録されていないツールまたはその他のスタンドアロン プロセスがある場合でも、タイトル パーティションでこれらを実行できます。 ただし、最初にタイトル パーティションをアクティブにする必要があります。 DevkitToolLauncher アプリケーションではこの点が考慮されており、サンプルの起動時にシステムによってタイトル パーティションがアクティブ化されます。 次に、DevkitTooling はツールまたはプロセスを
[CreateProcess](https://docs.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-createprocessa)
これはタイトル パーティション内にあり、完全なハードウェア リソース アクセス権を持ちます。

注: *xbrun.exe* ツールは、タイトル パーティションでアプリケーションを起動することもできます。 ただし、*xbrun.exe* では、タイトル パーティションが最初にアクティブであるとは保証されません。 タイトルが Xbox 開発キットで現在実行されている場合は、*xbrun.exe* の *"/x/title"* パラメーターで、実行可能ファイルをタイトル パーティションで実行するように指定しました。 *xbrun.exe* の詳細については、GDK ドキュメントを参照してください。

## ポートと Xbox ファイアウォール

Xbox 本体と Xbox 開発キットには、TCP と UDP の両方に対して、既定でほとんどの未承諾の受信接続要求を防ぐファイアウォールがあります。 リテール タイトルの場合、未承諾の受信 TCP は常にブロックされ、これを回避する方法はありません。 ただし、UDP は、*XNetworkingQueryPreferredLocalUDPMultiplayerPort\[Async\]* を使用して照会できる優先ローカル UDP マルチプレート ポートを使用できます。

Xbox 開発キットは、MicrosoftGame.config ファイルのエントリを介して、未承諾の受信 TCP パケットと UDP パケットを許可するように構成できます。

```
<?xml version="1.0" encoding="utf-8"?>
<Game configVersion="0">
...
  <DevelopmentOnly>
    <DebugNetworkPortList>
      <DebugNetworkPort>4600</DebugNetworkPort>
      <DebugNetworkPort>4601<DebugNetworkPort>
    </DebugNetworkPortList>
  </DevelopmentOnly>
</Game>
```


要求されていない受信接続を許可するポートごとに、別の *DebugNetworkPort* エントリを *DebugNetworkPortList* に追加する必要があります。 これは、TCP 経由で直接相互に通信する P2P ツールなどの場合に必要です。

MicrosoftGame.config ファイルが更新されたら、タイトルを更新時にピックアップするように再デプロイする必要があります。

## Xbox 開発キットの Win32 アプリケーション

タイトル パーティションでは、特定の Xbox 統合を行っていない Win32 コンソール アプリケーションを直接実行できます。 ただし、Win32 API の可用性は、Windows PC で通常使用できるものの除去されたサブセットです。

Win32 アプリケーションを使用可能な API のみに制限するには、Windows ヘッダーを含める前に *WINAPI_FAMILY* を *WINAPI_FAMILY_GAME* に定義する必要があります。

```
#define WINAPI_FAMILY WINAPI_FAMILY_GAMES
#include <Windows.h>
```


CPUTool プロジェクトは、この非常に単純な例です。 *WINAPI_FAMILY_GAMES* に制限されたコンソール Win32 アプリケーションをビルドします。 結果として、CPUTool.exe は Windows PC と Xbox 本体の両方で正常に実行できます。

## Xbox 開発キット上の GPU プロセス

タイトル パーティションで実行されているプロセスでは、D3D GPU の使用に関するより大きい制限があります。

* 一度に Direct3D を利用できるのは、タイトル パーティション内の 1 つのプロセスのみです。

* Xbox 固有の D3D12 デバイス メソッド *SuspendX/ResumeX* を使用して、D3D を利用する複数のプロセスを管理できます。 2 つのプロセスで D3D を同時にアクティブに利用することはできません。

* Xbox 固有の D3D ヘッダーとライブラリを使用する必要があります。

これらの考慮事項を不適切に処理すると、アプリケーションがクラッシュしたり、レンダリングが破損したり、本体がクラッシュしたりする可能性があります。 DevkitTooling サンプルでは、これに対処するため、GPU を利用するサブプロセスを作成する前に *SuspendX* を呼び出します。 そのサブプロセスが完全に終了すると、*ResumeX* を使用してサンプルのレンダリングが再度有効になります。

GPUTool プロジェクトは、画面上に三角形をレンダリングする単純なプロセスです。 これは、GPU に関する考慮事項が考慮されている場合に、タイトル パーティションで GPU サブプロセスを使用する方法を示すために使用されます。

## 複数のプロセスを含む GameInput

現在 (このサンプルの作成時に) GameInput ライブラリは、このサンプルの作成時に一度に 1 つ以上のプロセスで使用することはサポートされていません。 また、プロセス内でクリーンアップして再初期化したり、プロセスを終了して開始したりすることはできません。 その結果、GameInput を初期化する最初のプロセスが、それを使用できる唯一のプロセスです。 初期化を試みる将来のプロセスはクラッシュします。

サンプルをコンパイルして実行する場合、サンプルの使用状況を追跡するために、サンプルの実行可能ファイルのファイル名が Microsoft に送信されます。 このデータ コレクションからオプトアウトするには、Main.cpp の "サンプル使用状況テレメトリ" というラベルの付いたコードのブロックを削除します。
