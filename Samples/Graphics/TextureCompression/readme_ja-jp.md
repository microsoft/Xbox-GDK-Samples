# TextureCompression サンプル

*このサンプルは Microsoft Game Development Kit (2021 年 6 月) と互換性があります*

# 説明

このサンプルは、テクスチャ データの Scarlett プラットフォームで使用可能な新しいハードウェア解凍単位を使用する方法を示します。

# サンプルのビルド

Project Scarlett を使用している場合は、アクティブなソリューション プラットフォームを `Gaming.Xbox.Scarlett.x64` に設定します。

このサンプルでは、Xbox One はサポートされていません。

*詳細については、**GDK ドキュメント*の「__サンプルの実行__」 を参照してください。

# サンプルの使用方法

![自動的に生成されたロゴの [説明] のクローズ アップ](./media/image3.png)

このサンプルには、さまざまな BCn エンコードに対してどのような圧縮率でアーカイブできるかを説明するために、テクスチャの例がいくつか用意されています。 テクスチャとミップ レベルはコントローラーを使用して反転できます。

| 操作 | ゲームパッド |
|---|---|
| 次のテクスチャ | 方向パッド 上 |
| 前のテクスチャ | 方向パッド 下 |
| ミップ レベルを上げる | 方向パッド 右 |
| ミップ レベルを下げる | 方向パッド 左 |
| Exit | ビュー ボタン |

# 実装メモ

ハードウェア展開ユニットは、Direct Storage API を使用して NVMe コントローラーとパイプライン化されています。 要求で圧縮解除を有効にすると、NVMe ドライブからストリーミングされたデータは、メモリに書き込まれる前に、展開ユニットを通じて自動的にパイプ処理されます。 これを実現するために、プログラムでは中間バッファーや同期を行う必要がありません。 詳細については、GDK ドキュメントの「Direct Storage の概要」を参照してください。

サンプルに含まれている .xbtc テクスチャは、GDK の新しい XBTC 圧縮ツールを使用してオフラインで圧縮されたものです。 このツールは、DDS ファイルを使用して、さらに圧縮を実行します。そのために、Deflate (つまり、 Zlib) アルゴリズムと BCn でエンコードされたテクスチャ データ用に特別設計された独自の BCPack アルゴリズムの両方を使用します。 詳細については、GDK ドキュメントの「Xbox テクスチャ コンプレッサーの概要」を参照してください。

# 既知の問題

現在、xbtc ファイルが出力できる可能性のある PRT タイル形式はサポートされていません (XBTC.exe ツールの --tilemode オプションを参照)。

XG ライブラリのバグのため、サンプルの xbtc ファイルは標準タイル モード (\_S) で圧縮されています。 このサンプルの今後のバージョンでは、ネイティブ (\_D) タイル モードのサポートが有効になります (XBTC.exe ツールの --tilemode を参照してください)。

現在、すべての XBTC 圧縮は非破壊的です。 XBTC ロードマップ ドキュメントで概説されているように、GDK の将来のリリースでは、サイズと品質をトレードするためのオプションを導入する予定です。

# プライバシーに関する声明

サンプルをコンパイルして実行する場合、サンプルの使用状況を追跡するために、サンプルの実行可能ファイルのファイル名が Microsoft に送信されます。 このデータ コレクションからオプトアウトするには、Main.cpp の "サンプル使用状況テレメトリ" というラベルの付いたコードのブロックを削除します。

Microsoft のプライバシー ポリシー全般の詳細については、「[Microsoft のプライバシーに関する声明](https://privacy.microsoft.com/en-us/privacystatement/)」を参照してください。
