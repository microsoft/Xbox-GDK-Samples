#   SimpleVRS 示例

*\* 此示例与 Microsoft 游戏开发工具包（2020 年 11 月）兼容。*

# 

# 说明

此示例的目标是简洁地演示如何使用[第 2
层屏幕空间可变速率着色](https://docs.microsoft.com/en-us/windows/win32/direct3d12/vrs#tier-2)
(VRS) 来通过几行代码最大程度地降低昂贵的像素着色器成本。

可变速率着色 (VRS) 通过将像素的最终值广播到其相邻部分（通过 VRS D3D12
API
指定的影响区域）来减少像素着色器调用的总数。这非常适合场景中出现均匀着色或每像素细节少得多的区域。

在在此示例中，在移动半透明的云墙后面引入了经典的简单三角形，并使用人工昂贵的像素着色器进行渲染，以展示
VRS
着色率如何减少繁重的像素着色器工作量。 由于可见度降低，被半透明云像素部分遮挡的三角形像素以粗略速率着色。 对于生成的着色率图像和渲染的场景，使用平均已用
GPU
时间量来突出显示性能节省。还提供了一种可视化模式来说明场景中着色率的分配。

# 实现说明

此简单示例的主要目的是帮助用户熟悉启用第2层 VRS 并专注于 VRS
特有的性能优势。为了简化实现，省略了示例其余部分中的潜在简化和优化。

**SimpleVRS 中的渲染通道摘要 **

以下步骤总结并有助于此示例中每个帧的渲染： 

1.  清除所有渲染目标。 

2.  禁用之前设置的任何 VRS 状态，并将云子画面的 alpha
    值渲染到一个小缓冲区。 

3.  根据相似 alpha 值的分组填充着色速率图像，并使用新的着色速率图启用
    VRS。 

4.  使用人工昂贵的像素着色器渲染不透明的云子画面和三角形。 

**重要的 VRS API 组件和函数**

如示例的 AllocateShadingRateImage 函数所示，着色率图像 GPU 资源使用
**D3D12_RESOURCE_STATE_SHADING_RATE_SOURCE**
资源状态进行初始化，以便计算着色器可以使用着色率填充它。必须使用
[Direct3D 12 VRS
规范](https://microsoft.github.io/DirectX-Specs/d3d/VariableRateShading.html)中指定的
**DXGI_FORMAT_R8_UINT** 图像格式创建它。在 Scarlett 上，图块大小为
8x8。这意味着着色速率图像中的每个着色速率值都映射到全分辨率帧缓冲区中的
64 像素正方形。为了完全覆盖屏幕，着色速率图像尺寸是帧缓冲区的 1/64。

在渲染函数 (VRS.cpp) 中，通过 **RSSetShadingRate** 设置
**D3D12_SHADING_RATE_1X1** 着色速率来禁用
VRS，以便可以计算着色速率图像并以其全分辨率渲染。然后，使用
**RSSetShadingRate** 和
**RSSetShadingRateImage**设置着色速率图像，计算着色器完成后，使用适当的值填充着色速率图像。

**场景渲染**

在将三角形和全分辨率云精灵渲染到帧缓冲区之前，云精灵的 alpha
值将渲染到较小的离屏渲染目标中，由计算着色器处理以填充 VRS
屏幕空间图像。

此外，还添加了 ExpensiveShaderFunction (PixelShader.hlsl)
来使场景三角形的像素着色器足够昂贵，以展示使用粗略 VRS
着色速率带来的性能优势。

**VRS 屏幕空间图像确定**

着色速率是根据每个像素的水平和垂直 alpha
梯度以及完全透明像素的存在来选择的，以确定像素是否是云轮廓的一部分。属于垂直边缘的像素是使用
**D3D12_SHADING_RATE_1X2** 着色速率指定的，而属于水平边缘的像素是使用
**D3D12_SHADING_RATE_2X1**
分配的。**默认情况下，D3D12_SHADING_RATE_2X2**
被指定为计算属于任何水平-垂直交叉点的像素。对于云的轮廓，中心像素会针对任何透明像素进行额外检查，这可能意味着有一个垂直或水平边缘将云与其透明背景隔开。始终以全速率
(**D3D12_SHADING_RATE_1X1**) 分配完全透明像素。图 1
中演示了此着色速率计算的示例。
