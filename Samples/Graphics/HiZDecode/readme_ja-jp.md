# HiZDecode サンプル

*このサンプルは、Microsoft Game Development Kit と互換性があります (2022 年 3 月)*

# 説明

# このサンプルは、htile サーフェイスから HiZ の値を抽出する方法を示します。

![](./media/image2.jpeg)

# サンプルの使用方法

このサンプルでは、次のコントロールを使用します。

| 操作 | ゲームパッド |
|---|---|
| カメラを原点に近づけて/遠ざけて移動する | 左側のサムスティックを上げる/下げる |
| カメラの周回 | 右サムスティック |
| カメラのリセット | 右サムスティック (クリック) |
| ステンシルの切り替え | A ボタン |
| 再集計の切り替え | B ボタン |
| 深度圧縮の切り替え | Y ボタン |
| DRAM と ESRAM の深度の切り替え | X ボタン |
| 展開の切り替え | 方向パッド左右 |
| Exit | ビュー ボタン |

# サンプルのビルド

Xbox One 開発キットを使用している場合は、アクティブなソリューション プラットフォームを `Gaming.Xbox.XboxOne.x64` に設定します。

Xbox Series X|S 開発キットを使用している場合は、アクティブなソリューション プラットフォームを `Gaming.Xbox.Scarlett.x64` に設定します。

*詳細については、**GDK ドキュメント*の「__サンプルの実行__」を参照してください。

# 実装メモ

htile サーフェイスは、深度ステンシル バッファーに関連付けられたメタデータ サーフェイスです。 深度ステンシル バッファーの各 8x8 タイルには、関連付けられた 32 ビット htile エントリがあります。 htile エントリには、次の情報が含まれています:

- 保守的な最小深度と最大深度をエンコードするタイルの Hi z 情報

- タイルの Hi ステンシル情報。タイル内のすべてのピクセルがステンシルに関する特定のファクトに一致するかどうかを記録します。

- 深度圧縮メタデータ。タイルにクリア、圧縮、または展開された深度が含まれているかどうかをエンコードします

- ステンシル圧縮メタデータ。タイルにクリア、圧縮、または展開されたステンシル値が含まれているかどうかをエンコードします

このサンプルでは、htile の hi z および hi ステンシル部分をテクスチャにデコードする方法を示します。 これらのテクスチャは、次のようなさまざまな目的に使用できます。

- シーンのカリングを高速化する

- 照明用タイルの分類

(これらのアプリケーションはここでは示されていません)。

| | |
|---|---|
| このサンプルでは、デコードされた hi z および hi ステンシル テクスチャをサムネイル ビューに表示します。 Hi z サムネイルには、赤と青のチャンネルの最小深度と緑のチャネルの最大深度があります。 チャネルの選択により、深度の範囲が広いタイルには、引きずりが発生します。 Hi ステンシル のサムネイルには、赤いチャネルの Hi ステンシル テスト 0 の値と、緑のチャネルの Hi ステンシル テスト 1 の値が表示されます。 Xbox Series X の場合 | S htile 形式のため、緑色のチャネルは常に 0 に設定されます。 |

Htile エンコードは、ステンシルが関連付けられている深度バッファーに存在するかどうかによって異なります。 ステンシルが存在しない場合、最小深度と最大深度の両方が明示的な 14 ビット固定小数点値になります。 ステンシルが存在する場合、深度範囲の一方の端は明示的な 14 ビット固定小数点値であり、もう一方の端は 6 ビットデルタ値によって暗黙的に指定されます。 デルタでは、シェーダー コメントで説明されているカスタム エンコードが使用されます。

最大 2 つの Hi ステンシル テストがあり、各テストには次の 3 つの結果が考えられます。

1. タイル内にテストを満たすピクセルがありません

2. タイル内のすべてのピクセルがテストを満たす

3. 一部のピクセルはテストを満たし、一部のピクセルはテストを満たしていません (または、値が最新ではありません)

ドライバーは、(February 2015 XDK の時点で) Hi ステンシルの状態を自動的に選択します。 PIX GPU 状態ビューでは、レジスタから hi ステンシルの状態を読み取ることができます。

| | |
|---|---|
| `Context - DB - DB_SRESULTS_COMPARE_STATE\<0|1>` |

このサンプルには、"resummarize" パスを実行するオプションが用意されています。 このパスの所要時間は約 50 秒で、最新の深度データに対応するようにすべての htile 値が更新されます。 再集計パスがない場合、htile はまだ有効ですが、一部の hi z 範囲は必要以上に広くなります。また、一部の hi ステンシル値には、他のコードのいずれかが正しい場合でも、"知らない" コードが含まれます。

再集計のコストは、既存の展開操作と組み合わせることで償却できます。 通常、圧縮解除には、再集計の有無に関係なく、ほぼ同じ時間がかかります。

# 既知の問題

このサンプルは、将来変更される可能性がある特定のドライバーの選択に依存します:

- htile サーフェスがタイルまたは線形として作成されるかどうか

- htile サーフェイスに対して選択されるタイリング モード

ドライバーの制限により、このサンプルでは、圧縮されていないステンシル バッファーでの hi ステンシルの使用はサポートされていません。
