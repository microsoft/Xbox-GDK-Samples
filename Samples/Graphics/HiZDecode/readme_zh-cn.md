*此示例可用于 Microsoft 游戏开发工具包 （2022 年 3 月）*

# 实现说明

Htile 图面是与深度模具缓冲区关联的元数据图面。 深度模具缓冲区的每个 8x8 磁贴都有一个关联的 32 位 htile 条目。 htile 条目包含以下信息：

- 磁贴的 hi z 信息，编码了保守的最小深度和最大深度

- 磁贴的 hi 模具信息，记录磁贴中的所有像素是否匹配模具的某些情况。

- 深度压缩元数据，编码磁贴是否包含清晰、压缩或扩展的深度

- 模具压缩元数据，编码磁贴是否包含清晰、压缩或扩展的模具值

此示例演示如何将 htile 的 hi z 和 hi 模具部分解码到纹理上。 然后，这些纹理可用于各种用途，包括：

- 加速场景挑选

- 用于照明的磁贴分类

（此处未演示这些应用程序。）

| | |
|---|---|
| 此示例在缩略图视图中显示了解码的 hi z 和 hi 模具纹理。 hi z 缩略图在红色和蓝色通道中具有最小深度，在绿色通道中具有最大深度。 由于通道选择，深度范围较大的磁贴将具有绿色色调。 Hi 模具缩略图显示红色通道中 hi 模具测试 0 的值，以及绿色通道中 hi 模具测试 1 的值。 在 Xbox Series X 上 | 由于 htile 格式的限制，绿色通道始终设置为 0。 |

Htile 编码取决于模具是否存在于关联的深度缓冲区中。 如果模具不存在，最小深度和最大深度都将是明确的 14 位固定点值。 当存在模具时，深度范围的一端是明确的 14 位固定点值，另一端则按 6 位增量值算出。 增量将使用着色器注释中所述的自定义编码。

最多有两个 Hi 模具测试，每个测试都有三个可能的结果：

1. 磁贴中没有像素满足测试要求

2. 磁贴中的像素均满足测试要求

3. 某些像素满足测试要求，而某些像素不满足测试要求（或者说，该值不是最新数据）

驱动程序自动选择 hi 模具状态（自 2015 年 2 月 XDK 起）。 可以从寄存器读取 PIX GPU 状态视图中的 hi 模具状态：

| | |
|---|---|
| `Context - DB - DB_SRESULTS_COMPARE_STATE\<0|1>` |

该示例提供执行&ldquo;重新汇总&rdquo;传递的选项。 此过程大约需要 50 us，它会更新所有 htile 值，以便与最新的深度数据对应。 如果没有&ldquo;重新汇总&rdquo;传递，htile 仍然有效，但某些 hi z 范围将比必要的范围更广泛，某些 hi 模具值将包含&ldquo;不知道&rdquo;代码，即使其他代码中有一个代码是正确的。

通过将其与现有解压缩操作相结合，则可以分摊重新汇总的成本。 无论是否重新汇总，解压缩通常花费的时间都相同。

# 已知问题

此示例取决于某些驱动程序的选择（这些选择将来可能发生变化）：

- htile 图面是以平铺图面还是线性图面创建

- 为 htile 图面选择哪种平铺模式

由于驱动程序限制，该示例不支持在未压缩的模具缓冲区上使用 hi 模具。
