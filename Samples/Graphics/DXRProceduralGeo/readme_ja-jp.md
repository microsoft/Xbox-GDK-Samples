# DXR 手続き型ジオメトリ

*このサンプルは、Microsoft Game Development Kit (2023 年 3 月) および Windows 10 (バージョン 1903) 2019 年 5 月の更新プログラムと互換性があります*

# 説明

このサンプルでは、さまざまな種類の手続き型で生成されたジオメトリ (および床面を持つ三角形ベースの geo) の単純な DirectX レイトレーシング (DXR) 描画を示します。

![](./media/image01.png)

# サンプルのビルド

Project Scarlett を使用している場合は、アクティブなソリューション プラットフォームを `Gaming.Xbox.Scarlett.x64` に設定します。

適切なハードウェアと Windows 10 リリースで PC を使用する場合は、アクティブなソリューション プラットフォームを `Gaming.Deskop.x64` に設定します。

このサンプルでは、Xbox One はサポートされていません。

*詳細については、**GDK ドキュメント*の「__サンプルの実行__」 を参照してください。

# サンプルの使用方法

このサンプルでは、フリー カメラを使用して移動できます (ゲームパッドの左右のスティックで制御でき、方向キー + マウスを使用して制御することもできます)。 A ボタン/C キー (ゲームパッド/キーボード) を押すと、ジオメトリ アニメーションが切り替わります。 ジオメトリの既定値はアニメーション化されます。 B ボタン/V キーを押すと、シャドウ キャスト ライト アニメーションが切り替わります。 ライト アニメーションの既定値はオフです。

# Controls

| 操作 | ゲームパッド | キーボード |
|---|---|---|
| アニメーション ジオメトリの切り替え | A | C |
| アニメーション ライトを切り替える | B | V |
| Exit | ビュー ボタン | Esc キー |

# 実装メモ

このサンプルでは、三角形と手続き的に生成されたジオメトリの両方で DXR を使用する方法を示します。 1 つ目は、下部レベルの加速構造 (BLAS) にジオメトリに準拠する三角形を含み、光線が加速構造の葉と交差するたびにヒットが登録されます。 トラバース後、光線がジオメトリと交差したかどうかに応じて、ミスシェーダまたは最接近ヒット シェーダが実行されます。

手続き型で生成されたジオメトリの場合、BLAS はジオメトリを保持しません。 代わりに、AABB (D3D12_RAYTRACING_AABB) の定義が含まれています。 光線が AABB と再び交差するたびに、光線がジオメトリと交差するかどうかを決定するカスタム ロジックを持つ交差シェーダーが実行されます。 トラバースの最後には、ヒットが登録されたかどうかに応じて、最接近ヒット シェーダーまたはミス シェーダーも実行されます。

(光線が交差するジオメトリに応じて) 実行するシェーダーを決定するには、シェーダー テーブル レコードを含むシェーダー テーブルが使用されます。 これらは、32 バイトシェーダーのインデントと、ローカルにバインドされる一連のローカル ルート パラメーターで構成されます。 後で traceRay を呼び出すときに、dispathRays 呼び出しに含まれる情報、traceRay 呼び出し、および (BLAS からの) ジオメトリを使用して、テーブル上の正しいエントリのインデックスを作成します。 このサンプルでは、レイ ジェネレーション シェーダー テーブル (エントリが 1 つ)、ミス シェーダー テーブル (シェーディング用とシャドウ ミス用のエントリの 2 つ)、ヒット シェーダー テーブル (22 エントリ、プリミティブ型ごとに 1 つ)、およびヒット シェーダー テーブルを定義します。

2 つの下部レベルアクセラレーション構造 (BLAS) があり、1 つは三角形のジオメトリ (2 つの三角形で構成される床面) を含み、もう 1 つは軸に配置されたすべての境界ボックス (AABB) を含みます。 TLAS は、この BLASes ごとに 1 つのインスタンスを保持します。 TLAS と BLAS は、このサンプルのフレームの開始時に構築され、更新されていません。

ミス シェーダーは、見逃して UAV に黒を書き込むすべての光線に対して呼び出されます (これは、DispatchRays 呼び出しの前に UAV を黒に事前にクリアする代わりに行われます)。

Raygen シェーダーは、パースペクティブ プロジェクションを使用して、ピクセルごとに 1 つの光線をシーンにキャストします。 ヒットが登録されると、さらに 2 つの光線がキャストされます。 シャドウをテストする 1 つで、シャドウ キャスト シーン ライトの方向に移動します。もう 1 つは、受信光線と交差ポイントのジオメトリの法線に基づいて反射トレイクトリーを計算します。 シャドウ光線は、このポイントが隠れているかどうかを判断しますが、反射光線はシーンのジオメトリに対して反射のコントリビューションをチェックします。 反射と影には、停止する前に 3 つのバウンス (再帰制限) の制限があります。

最も近いヒット シェーダーは、プリミティブの素材情報、ポイントがシャドウにあるかどうか、アンビエント ライト情報、および他のジオメトリからの反射コントリビューションが存在するかどうかに基づいてシェーディングを担当します。

# 注意

- 調査中に、/Od を使用して Scarlett で DXR を使用してコンパイルすると視覚的なアーティファクトが発生するバグがあります。 このため、デバッグ構成では、その時点で /Od が使用されていません。 これは、バグが修正されたら修正する必要があります。
- 入れ子になった traceRay 呼び出しで使用すると、組み込み関数にバグが発生する可能性があります。 それまでの間、この使用状況をコメントアウトします。
- コンピューティング スクラッチが割り当てられないため、検証に失敗したときにサンプルがクラッシュするドライバーのバグがあります (コンピューティングと DXR スクラッチはプールではないため、これは必要ありません)。 これは 2023 年 6 月に修正されましたが、2303 (3 月) の検証済みドライバーでサンプルがスローされます。 これは、3 月のデバッグ構成で例外がスローされることを意味します。 サンプルはプロファイルとリリースで正常に実行されます。 これは、ドライバーのバグが修正されたら更新する必要があります。

# プライバシーに関する声明

サンプルをコンパイルして実行する場合、サンプルの使用状況を追跡するために、サンプルの実行可能ファイルのファイル名が Microsoft に送信されます。 このデータ コレクションからオプトアウトするには、Main.cpp の "サンプル使用状況テレメトリ" というラベルの付いたコードのブロックを削除します。

Microsoft のプライバシー ポリシー全般の詳細については、「[Microsoft のプライバシーに関する声明](https://privacy.microsoft.com/en-us/privacystatement/)」を参照してください。
