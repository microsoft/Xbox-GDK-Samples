*このサンプルは、Microsoft ゲーム開発キットのプレビュー (2019 年 11 月)

# 

# 説明

このサンプルでは、Xbox 専用の機能である DrawIndexedX
を使用する方法を示します。この機能は、複数の連続した描画呼び出しのスレッドを
1 つのウェーブにまとめて、1
つの描画として実行します。これは単一インスタンスの場合に
DrawIndexedInstanced
の代わりに使用できます。複数のインスタンスがある場合、DrawIndexedX
はインスタンスごとに個別に呼び出すことができます。また、インスタンス
データは、正しいインスタンスを特定する数ビットのインデックス
バッファーと共にバッファーに渡すことができます。パッキングは描画呼び出しの間に状態変更がない場合にのみ発生します。状態が変更された場合、描画呼び出しは
DrawIndexedInstanced と同じように動作します。DrawIndexedX
の各呼び出しでは、インデックス バッファーとインデックス
バッファー形式のみを変更できます。オフセットを渡して、頂点バッファーへのオフセットを指定できます。頂点バッファーを、すべての頂点データを含む
1 つのバッファーにまとめる必要があります。シェーダーの描画呼び出し (描画
ID) を識別しやすくするために、インデックス
バッファーの数ビットをデータの受け渡しに使用できます。描画呼び出しに固有のその他のデータを、描画
ID
を使用して構造化バッファーに渡したり、抽出したりできます。これを使用することで改善が見られる最も簡単な場所は、深度パスです。通常は状態変更が必要なく、スレッドを結合できるためです。カラー
パス中に改善が見られることがありますが、スレッドの結合によって発生する発散量に依存します。**Xbox
One X では、一部のハードウェア設定のため、この機能は
DrawIndexedInstanced と同じように動作します。**

void DrawIndexedX(

> D3D12_GPU_VIRTUAL_ADDRESS *IndexBufferLocation*,
>
> DXGI_FORMAT *IndexFormat*,
>
> UINT *IndexCount*,
>
> UINT *IndexOffset*

);

DrawIndexedX をサポートするために既存のシェーダー コードに必要な変更:

-   DrawID や materialID などの他の情報を含むようにインデックス
    バッファー
    データに埋め込みがなされている可能性があるため、描画の頂点 ID を
    SV_VERTEXID から抽出する必要があります。構造化バッファー (DrawID
    に基づいてインデックスを作成できる)
    を使用して、シェーダーに追加データを渡すことができます。

-   描画ごとに変わる記述子を、SRV のピクセル
    シェーダーに示されているように配列に移動する必要があります。

-   1
    つのウェーブ内のスレッド間で値が異なる可能性があるときは、NonUniformResourceIndex
    キーワードの使用が必要になることがあります。キーワードがない場合、シェーダーは、ウェーブ内のすべてのスレッドで値が一様であると想定します。

サンプル内の単純なシーンの観察:

-   深度パスは、DrawIndexedX を使用すると時間がわずかに短縮されます。

-   シーンに対して生成される VS ウェーブの数が (2438 から 2183 へと)
    減少します。

-   SRV のテクスチャ配列を使用する場合、ピクセル
    シェーダーのウェーブの約 1 ～ 2% のみが発散します。

Xbox One の devkit を使用している場合は、アクティブなソリューション
プラットフォームを Gaming.Xbox.XboxOne.x64 に設定します。

Xbox One および Xbox One S にのみ適用されます。

# 実装に関する注意事項

このサンプルでは次のパスを実行します。

-   深度のみのパス

> このパスの場合、頂点シェーダーが分岐する必要がなく、ピクセル
> シェーダーのウェーブがないため、DrawIndexedX
> から最大のメリットが得られます。したがって、すべての呼び出しをまとめて
> 1 つの描画として実行できます。

-   デバッグのみ -- ウェーブの総数

フレームの頂点シェーダーおよびピクセル
シェーダーに渡されたウェーブの総数をカウントするパス。

-   深度 EQUALS のメッシュ レンダー (色) パス

    -   このパスは、最終的なバッファーにメッシュを描画し、テクスチャを適用します。描画呼び出しによって異なる素材が使用されます。この素材データはインデックス
        バッファー情報と共に渡されます。32 ビットのインデックス
        バッファーの余分な未使用ビットを使用して、シェーダーによって実行されている描画呼び出しを特定できます。描画
        ID に基づいて、素材 ID
        などのその他の情報を抽出し、定数バッファー内のピクセル
        シェーダーに渡すことができます。

> uint actualVertexID = vertexID & 0xFFFFF;
>
> uint materialIndex = (vertexID \>\> 20) & MAX_MATERIALS;

-   DrawIndexedX
    の場合、各モデルに異なる素材を渡すことにより、ウェーブ内で発散が生じる場合があります。複数のテクスチャのアトラスを使用すると、発散を減らすことができます。このサンプルでは、すべてのテクスチャのアトラスを使用して、その場合に発散が完全に除去される様子を示しています。

ウェーブ数の減少を確認するには、PIX の次のカウンターを確認します。

-   SPI_PERF_VS_WAVE

描画呼び出し用に生成された VS
ウェーブの数を示します。DrawIndexedXPerformanceGroup
の数値を確認します。これは、DrawIndexedInstanced
を使用したときに生成されたウェーブの数よりも少ないはずです。サンプルで示すように、これはシェーダー内でも計算できます。

-   SPI_PERF_PS_CTL_WAVE

描画呼び出し用に生成された PS ウェーブの数を示します。

-   VGT_PERF_VGT_PA_CLIPP_EOP / 2

実行された描画呼び出しの数を示します。状態変更が発生した場合、描画は別のグループに分割され、この数値は、作成された個別のバッチ
(描画) の数を示します。

-   また、PIX
    を確認して、コンテキストが描画呼び出しにどのように使用されるかを確認できます。

# 既知の問題

この機能は、一部のハードウェア設定のため、Xbox One X では
DrawIndexedInstanced と同じように動作します。
