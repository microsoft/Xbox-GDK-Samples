#   PixelBinning Sample

*このサンプルは Microsoft Game Development Kit (2020 年 8 月)
と互換性があります*

# 説明

このサンプルでは、ピクセルを各ピクセルに関連付けられた ID
で並べ替えて、同じ ID または異なる ID
の最小限のセットを使用し、ウェーブ処理ピクセルを使用してコンピューティング
ワークロードを後でディスパッチする方法を示します。

サンプルのレンダリング ループは、すべてのピクセルの
ID/キーの生成から始まります。これは、範囲 (0 \... ビンの数)
のランダムな値を取ります。その後、ビン分割 (または部分的な並べ替え)
パスはピクセルを再配置し、パックされたピクセル座標を格納する 32
ビット要素のバッファーを生成します。「Figure 1」を参照してください

![](./media/image3.png)

図 1.画像全体のビン分割の例。同じ ID
を持つピクセルのすべての座標は、メモリに隣接して格納されます。ピクセル座標のこの間接バッファーを使用すると、同じ
ID を持つピクセルのグループごとに異なるコンピューティング
カーネルをディスパッチできます。

ビン分割パスは、2 つのモードで動作できます。最初のモードは、*グローバル*
モードで、画像全体 (Figure 1) から同じ ID を持つピクセルを収集します。2
番目のモードは、*ローカル*で、画像全体ではなく、特定のサイズのマクロ
タイル内でのみピクセルを収集します (Figure
2)。アプリケーションによっては、一方のモードが他方よりも適している可能性があります。

たとえば、同じ ID
を持つピクセルを一緒に処理することでワークロードのパフォーマンスを向上でき、同じ
ID が分岐しないデータの処理を示している場合、ローカル
モードでは間接バッファーからのピクセルを処理するすべての個々のウェーブ内のデータの相違を減らすことができるため、ローカル
モードが役に立つ可能性があります。このようなワークロードは、レイトレーシング
ワークロードの可能性があります。この場合、任意の光線を処理するウェーブよりも、より空間的にコヒーレントな光線を処理するウェーブの方がかかる時間が短くなります
(Deligiannis & Schmid, 2019)。

グローバル
ビン分割は、すべての種類のピクセルを処理する汎用のコンピューティング
カーネルよりも、特殊なコンピューティング
カーネルが間接バッファーからの同じ ID
を持つピクセルを処理できる場合に役立つ可能性があります。タイルベースの
(Garawany, 2016) (Turanszki,
2020)分類アプローチとして普及すると、グローバル
ビン分割の優れた候補になります。ピクセルではなくタイルを分類する必要がある場合、入力テクスチャは、タイルの
ID をピクセル単位で格納する解像度の低いテクスチャにすることができます。

![](./media/image4.png)

図 2.マクロ タイル内のビン分割の例。サイズが 4x2 の同じマクロ
タイルからの同じ ID
を持つピクセルが隣接して格納されます。このモードでは、ピクセル ID
ごとにシェーダーを変更することはできませんが、ウェーブフロントが同じ ID
を持つピクセルを処理する可能性は高くなります。

# サンプルの使用方法

このサンプルは、解像度、ピクセルの並べ替えに使用される
ID/キーのビット幅、並べ替えの局所性、並べ替え中の一時使用専用のメモリ割り当てに応じて、並べ替えのパフォーマンス特性を示す多くのオプションを提供します。

![](./media/image5.png)

図 3.類似した色のピクセルが、並べ替えに使用されるのと同じ
ID/キーを持つカラー マップ。この場合、8 つの ID のみが使用されます
\[0:7\]。

このサンプルには、生成されるデータとピクセル
ビン分割のしくみを理解するための視覚化モードがいくつかあります。カラー
マップ (Figure 3) では、すべての一意のピクセル ID
に一意の色を割り当てて、同じ ID を持つピクセルの領域を強調表示します。A
ボタンを押すと、視覚化モードを切り替えることができます。

そのうちの 1
つは、ビン分割パスの後にピクセル座標を含む間接バッファーを示しています
(Figure 4)。ビン分割モード (*グローバル*または*ローカル*)
に応じて、バッファーの内容は異なる方法で視覚化されます。グローバル
ビン分割モードの場合、各ピクセルは、インデックスに格納されているバッファーの要素の
ID
を示します。これは、ピクセルの垂直方向の座標とピクセル単位の水平方向の解像度を乗算し、それにピクセルの水平方向の座標
(行優先順) を追加することによって計算されます。ローカル
ビン分割モードの場合、視覚化はもう少し複雑ですが、考え方は同じです。すべてのマクロ
タイルには、マクロ
タイル内のピクセル数と同じサイズのバッファーの一部が表示されます。

![](./media/image6.png)![](./media/image7.png){width="6.5in"
height="1.8263888888888888in"}

図 4.間接バッファーの視覚化。左側の画像 -- グローバル
ビン分割後の結果のバッファー、右側 -- ローカル
ビン分割後の結果のバッファー。

もう 1 つの視覚化モードは、相違ヒート マップ (Figure 5)
です。各*マイクロ タイル*は、それらが含まれている一意の ID
の数に応じて色付けされ、*マクロ タイル*の形状が強調表示されます (Figure
6)。

![](./media/image10.png)

図 5.サイズが 64 x 32 のマイクロ タイルで使用される一意の ID
の数を示す差異ヒート マップの例。この数は、マイクロ
タイルのピクセルの合計数または ID
の最大数のうち小さい方の数に対して相対的に示されます。この場合は
min(2048, 8) になります。たとえば、マイクロ タイル内のピクセルの ID が
1、5、6 の場合、ヒート マップには、このタイルのレート 3/8=0.375
に対応するカラー キーが含まれます。

マクロ タイルのサイズは、複数のマイクロ
タイルのサイズになります。このサンプルでは、ビン分割パスによる一時的な使用のために制御可能なメモリ割り当てがサポートされているため、2
種類のタイルの内部的な違いが存在します。この割り当ては、4
バイト要素の数として指定されます。すべてのマクロ タイルには、固定数の 4
バイト要素が必要です。これは、マクロ
タイルの合計数はメモリ割り当てによって異なることを意味します。

マクロ
タイルのサイズは、間接バッファー内のピクセル座標の順序も制御します。マクロ
タイルのサイズが大きいほど、順序が弱くなります。たとえば、マクロ
タイルのサイズが画像全体のサイズ以上の場合、同じマイクロ
タイルからの同じ ID
を持つピクセルのグループの位置は、最終的なシーケンス内で不確定になります。一方、マクロ
タイルのサイズがマイクロ
タイルと同じ場合、ピクセルのグループの位置は、最終的なシーケンス内で確定的になります。同じマイクロ
タイルからのピクセルの座標は常にメモリ内で隣接して格納されますが、マイクロ
タイル内での順序も不確定です。

![](./media/image11.png)

図 6.マクロ タイルの形状が複数のマイクロ タイル (この場合は 4x2)
の倍数であることを示す差異ヒート マップ。マクロ
タイルの形状は、チェッカーボードのパターンに従って、少し暗い色のトーンが配置された領域として示されます。

| 操作                                   |  ゲームパッド                |
|----------------------------------------|-----------------------------|

| 4 バイト カウンターの数を減らす        |  LB                          |

| ビンの数を減らす                       |  LT                          |
| 解像度を上げる                         |  方向パッド右方向            |
| 解像度を上げる                         |  方向パッド左方向            |
| ローカルビ ン分割とグローバルビン分割を切り替える |  Y |
| キー カラー マッ プ、差異マップ、並べ替えられたピクセル バッファーの視覚化を切り替える |  A |

# 実装上の注意

ピクセル
ビン分割、関連する視覚化、および正確性テストを行うすべてのコードは、次の
2 つのファイルに存在します。*PixelBinner.h/.cpp*
これらのファイルは、小さなドロップイン
ライブラリを形成します。*PixelBinner.h* には、提供されている
pixelBinner\* API の使用方法に関する広範なドキュメントが含まれています。

このサンプルには、いくつかのステップが含まれています。最初のステップでは、ピクセル
ID の出力に使用される 2d シンプレックス ノイズ (Quilez, 2013)
が生成されます。2 番目のステップは、複数のコンピューティング
カーネルをディスパッチすることによって機能するビン分割パス自体
(または部分的な並べ替え) です。

最初のカーネルは、サイズ 512/1024 スレッドのスレッド
グループで構成され、選択したスレッドグループのサイズに応じて、サイズ 64
x 32 または 64 x 64 ピクセルの 1 つの*マイクロ
タイル*を処理します。このカーネルは、処理されたマイクロ
タイル内の指定された範囲内のすべての ID
に関連付けられているピクセル数をカウントします。最も広いサポートされている
ID の範囲は \[0:2047\]
です。このようなスレッドグループが完了する直前に、マクロ タイルごと、ID
ごとにグローバル カウンターがインクリメントされます。

次の 1 つまたは 2 つのカーネル (マクロ タイルの数に応じて決まります)
は、最初のカーネルによって書き込まれたカウンターのグローバル排他プレフィックスの合計を計算します。

最後のカーネルは、最初のカーネルと同じ操作セットで始まりますが、グローバル包括プレフィックスの合計をフェッチした後、間接バッファーの適切な場所にピクセル座標を書き込みます。この手順では、ビン分割パスを最終処理します。ピクセル座標を含む間接バッファーは、このステップが完了するとすぐに使用できます。

*ExecuteIndirect*
の引数のバッファーを出力するオプションのカーネルもあります。このカーネルは、*グローバル*
ビン分割にのみ使用されます。これは、すべての ID
の間接ディスパッチ引数とルート定数を計算します。

これにより、すべての ID
の一意のシェーダーをディスパッチする機会が得られます。

ビン分割パスが完了した後に、いくつかのオプションの視覚化パスと、正確性チェックを行うパスがあります。後者は、サンプルのレンダリング
ループを終了します。

# 既知の問題

-   ビン分割/分類から除外する必要がある ID
    の特別な処理はありません。これは、それらの処理に、まだゼロ以外のコストがあることを意味します。
