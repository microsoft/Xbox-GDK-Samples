#   PixelBinning 示例

*此示例与 Microsoft 游戏开发工具包（2020 年 8 月）兼容*

# 说明

此示例演示如何按与每个像素关联的 ID 对像素进行排序，以便稍后使用具有相同
ID 或具有最小一组不同 ID 的波处理像素来分派计算工作负载。

示例的渲染循环从为每个像素生成 ID/键开始，它采用 \[0 \...
箱数量）范围内的随机值。然后，分箱（或部分排序）传递重新排列像素，并生成存储打包像素坐标的
32 位元素缓冲区。请参阅 Figure 1

![](./media/image3.png)

图 1.跨整个图像进行分箱的示例。ID
相同的像素的所有坐标都以相邻方式存储在内存中。这种像素坐标的间接缓冲区可用于为具有相同
ID 的每组像素分派不同的计算内核。

分箱传递可以在两种模式下运行。第一种模式为*全局*模式，它从整个图像
(Figure 1) 中收集 ID
相同的像素。第二种模式为*局部*模式；它只收集给定大小的宏图块内的像素，而不是整个图像
(Figure 2)。根据应用程序，可能是一种模式比另一种模式更合适。

例如，当可以通过一起处理 ID 相同的像素来提高工作负载的性能，并且相同 ID
指示处理非发散数据时，局部模式可能非常有用，因为它可减少处理间接缓冲区中像素的每个波中的数据散度。这种工作负载可以是光线追踪工作负载，其中波处理空间相干光线所需的时间比波处理任意光线要少
(Deligiannis & Schmid, 2019)。

如果专用计算内核处理间接缓冲区中 ID
相同之像素的速度比处理所有类型的像素的通用计算内核更快，则全局分箱非常有用。成为更常用的基于图块的
(Garawany, 2016) (Turanszki,
2020)分类方法是全局分箱的绝佳候选项。如果需要对图块而不是像素进行分类，则输入纹理可以只是一个分辨率较低的纹理，每个像素都存储图块的
ID。

![](./media/image4.png)

图 2.宏图块内的分箱示例。ID 相同且来自大小为 4x2
的宏图块的像素将以相邻方式存储。此模式不允许更改每个像素 ID 的着色器，但
wavefront 处理 ID 相同的像素的机会更高。

# 使用示例

该示例提供了许多选项来演示排序的性能特征，具体取决于分辨率、用于对像素进行排序的
ID/键的位宽度、排序局部性和在排序期间专门临时使用的内存预算。

![](./media/image5.png)

图 3.一种颜色图，其中颜色相似的像素具有用于排序的相同
ID/键。在本例中，仅使用 8 个 ID \[0:7\]。

该示例具有多种可视化模式，有助于了解生成的数据以及像素分箱的工作原理。颜色图
(Figure 3) 为每个唯一像素 ID 分配唯一颜色，以突出显示具有相同 ID
的像素区域。通过按 A 按钮，可以在可视化模式之间切换。

其中一种模式显示了分箱传递 (Figure 4)
后包含像素坐标的间接缓冲区。根据分箱模式（*全局*或*局部*），缓冲区内容的可视化方式不同。对于全局分箱模式，每个像素都显示存储在索引处的缓冲区元素的
ID，这是通过将像素的垂直坐标乘以像素的水平分辨率并加上像素的水平坐标（行优先顺序）来计算的。对于局部分箱模式，可视化有点复杂，但理想是相同的：每个宏图块显示缓冲区的一部分，大小等于宏图块中的像素数。

另一种可视化模式是散度热度地图 (Figure 5)。它根据每个*微图块*包含的唯一
ID 数量为每个微图块着色，并突出显示*宏图块* (Figure 6) 的形状。

![](./media/image10.png)

图 5.散度热度地图示例，显示大小为 64x32 的每个微图块中使用的唯一 ID
数量（相对于微图块中的像素总数）或最大 ID
数目，具体取决于哪个值更小，在本例中为 min(2048,
8)。例如，如果微图块中像素的 ID 为 1、5、6，则热度地图包含对应于此图块的
3/8=0.375 比率的颜色键。

宏图块具有多个微图块的大小。两种类型的图块之间存在内部区别，因为示例支持可控制的内存预算以供分箱传递临时使用。此预算指定为
4 字节元素的数量。每个宏图块都需要固定数量的 4
字节元素，这意味着宏图块总数因内存预算而异。

宏图块的大小还控制间接缓冲区中像素坐标的排序。宏图块的大小越大，
排序越弱。例如，如果宏图块的大小大于或等于整个图像的大小，则 ID
相同的一组像素的位置在最终序列中是不确定的。另一方面，如果宏图块的大小与微图块相同，则像素组在最终序列中的位置是确定的。同一微图块中的像素坐标始终以相邻方式存储在内存中，但它们在微图块中的顺序也是不确定的。

![](./media/image11.png)

图 6.散度热度地图，显示宏图块的形状可以是多个微图块的倍数（在本例中为
4x2）。宏图块的形状显示为区域，根据棋盘模式排列的颜色色调略暗。

# 实现说明

执行像素分箱、相关可视化和正确性测试的所有代码都存在于两个文件中：*PixelBinner.h/.cpp*
这些文件形成了一个小型的嵌入式库。*PixelBinner.h* 包含有关如何使用提供的
pixelBinner\* API 的大量文档。

该示例包含几个步骤。第一步生成用于输出像素 ID 的 2d 单纯形噪声 (Quilez,
2013)。第二步是分箱传递本身（或部分排序），它通过分配多个计算内核来工作。

第一个内核由大小为 512/1024 线程的线程组组成，其处理大小为 64x32 或
64x64
像素的单个*微图块*，具体取决于所选线程组的大小。此内核计算与处理后的微图块中指定范围内的每个
ID 关联的像素数。最广泛支持的 ID 范围是
\[0:2047\]。在此类线程组完成之前，它会为每个宏图块的每个 ID
递增全局计数器。

以下一个或两个内核（取决于宏图块的数量）计算由第一个内核写入的计数器的全局独占前缀和。

最后一个内核从与第一个内核相同的操作集开始，但在提取全局包含前缀和后，还会将像素坐标写入间接缓冲区的适当位置。此步骤将完成分箱传递。包含像素坐标的间接缓冲区已准备好在此步骤完成时使用。

还有一个可选内核，它为 *ExecuteIndirect*
输出参数缓冲区。此内核仅用于*全局*分箱。它计算每个 ID
的间接分派参数和根常量。

这提供了为每个 ID 分派唯一着色器的机会。

分箱传递完成后，会有几个可选的可视化传递以及执行正确性检查的传递。后者将完成示例的渲染循环。
