#   PixelBinning 샘플

*이 샘플은 Microsoft 게임 개발 키트(2020년 8월)와 호환됨*

# 설명

이 샘플은 각 픽셀과 연결된 ID별로 픽셀을 정렬하여 나중에 동일한 ID 또는
동일하지 않은 최소 ID 집합으로 웨이브 처리 픽셀을 사용하여 컴퓨팅
워크로드를 디스패치하는 방법을 보여줍니다.

샘플의 렌더링 루프는 \[0 \... 빈 수) 범위에서 임의의 값을 취하는 모든
픽셀에 대해 ID/키를 생성하는 것으로 시작합니다. 그런 다음 비닝(또는 부분
정렬) 패스는 픽셀을 재정렬하고 압축된 픽셀 좌표를 저장하는 32비트 요소의
버퍼를 생성합니다. Figure 1 참조

![](./media/image3.png)

그림 1. 전체 이미지에 대한 비닝의 예입니다. 동일한 ID를 가진 픽셀의 모든
좌표는 메모리에 인접하게 저장됩니다. 픽셀 좌표의 이 간접 버퍼를 사용하여
동일한 ID를 가진 각 픽셀 그룹에 대해 서로 다른 컴퓨팅 커널을 디스패치할
수 있습니다.

비닝 패스는 두 가지 모드로 작동할 수 있습니다. 첫 번째는 전체
이미지(Figure 1)에서 동일한 ID를 가진 픽셀을 수집하는 *전역* 모드입니다.
두 번째 모드는 *로컬*입니다. 전체 이미지가 아닌 지정된 크기의 매크로
타일 내에서만 픽셀을 수집합니다(Figure 2) 애플리케이션에 따라 한 모드가
다른 모드보다 더 적합할 수 있습니다.

예를 들어 동일한 ID의 픽셀을 함께 처리하여 워크로드의 성능을 향상시킬 수
있고 동일한 ID가 서로 다른 데이터를 처리함을 나타내는 경우 로컬 모드는
간접 참조 버퍼에서 픽셀을 처리하는 모든 개별 웨이브 내에서 데이터
불일치를 줄일 수 있으므로 도움이 될 수 있습니다. 이러한 워크로드는
공간적으로 더 일관성 있는 광선을 처리하는 웨이브가 임의의 광선을
처리하는 웨이브보다 시간이 덜 걸리는 레이트레이싱 워크로드가 될 수
있습니다 (Deligiannis & Schmid, 2019).

전역 비닝은 특수 컴퓨팅 커널이 모든 유형의 픽셀을 처리하는 일반 컴퓨팅
커널보다 훨씬 빠르게 간접 참조 버퍼에서 동일한 ID를 가진 픽셀을 처리할
수 있는 경우에 유용할 수 있습니다. 타일 ​​기반 (Garawany, 2016)
(Turanszki, 2020) 분류 접근 방식이 점점 더 대중화되면서 전역 비닝을 위한
훌륭한 후보가 되었습니다. 픽셀 대신 타일을 분류해야 하는 경우 입력
텍스처는 픽셀당 타일 ID를 저장하는 저해상도 텍스처일 수 있습니다.

![](./media/image4.png)

그림 2. 매크로 타일 내 비닝의 예입니다. id가 같고 크기가 4x2인 동일한
매크로 타일의 픽셀이 인접하여 저장됩니다. 이 모드에서는 픽셀 ID당
셰이더를 변경할 수 없지만 웨이브프론트가 동일한 ID를 가진 픽셀을 처리할
가능성이 더 높습니다.

# 샘플 사용

이 샘플은 해상도, 픽셀 정렬에 사용되는 ID/키의 비트 너비, 정렬 지역 및
정렬 중 임시 사용 전용 메모리 예산에 따라 정렬의 성능 특성을 시연하는
많은 옵션을 제공합니다.

![](./media/image5.png)

그림 3. 유사한 색상의 픽셀이 정렬에 사용된 동일한 ID/키를 갖는 색상 맵.
이 경우 8개의 ID만 사용됩니다\[0:7\].

샘플에는 생성되는 데이터와 픽셀 비닝의 작동 방식에 대한 아이디어를
제공하는 여러 시각화 모드가 있습니다. 색상 맵(Figure 3)은 모든 고유한
픽셀 ID에 고유한 색상을 할당하여 동일한 ID를 가진 픽셀 영역을 강조
표시합니다. A 버튼을 누르면 시각화 모드 사이를 전환할 수 있습니다.

그 중 하나는 비닝 패스(Figure 4) 이후의 픽셀 좌표를 포함하는 간접 참조
버퍼를 보여줍니다. 비닝 모드(*글로벌* 또는 *로컬*)에 따라 버퍼의 내용이
다르게 시각화됩니다. 전역 비닝 모드의 경우 각 픽셀은 픽셀의 수직 좌표에
픽셀 단위의 수평 해상도를 곱하고 픽셀의 수평 좌표(행 우선 순위)를 더하여
계산된 인덱스에 저장된 버퍼 요소의 ID를 보여줍니다. 로컬 비닝 모드의
경우 시각화가 조금 더 복잡하지만 아이디어는 동일합니다. 모든 매크로
타일은 매크로 타일의 픽셀 수와 동일한 크기의 버퍼 부분을 표시합니다.

![](./media/image6.png)![](./media/image7.png){width="6.5in"
height="1.8263888888888888in"}

그림 4. 간접 버퍼의 시각화. 왼쪽 이미지 -- 전역 비닝 후 결과 버퍼,
오른쪽 -- 로컬 비닝 후 결과 버퍼.

또 다른 시각화 모드는 발산 열 지도(Figure 5)입니다. 포함된 고유 ID 수에
따라 각 *마이크로 타일*에 색상을 지정하고 *매크로 타일*(Figure 6)의
모양을 강조 표시합니다.

![](./media/image10.png)

그림 5. 마이크로 타일의 총 픽셀 수 또는 더 작은 값에 따라 최대 ID 수와
관련하여 크기가 64x32인 모든 마이크로 타일에서 얼마나 많은 고유 ID가
사용되는지 보여주는 발산 히트 맵의 예 -- 이 경우 최소 (2048, 8). 예를
들어, 마이크로 타일의 픽셀에 ID가 1, 5, 6인 경우 히트 맵에는 이 타일의
비율 3/8=0.375에 해당하는 색상 키가 포함됩니다.

매크로 타일은 여러 개의 마이크로 타일 크기입니다. 샘플이 비닝 단계에서
일시적으로 사용하기 위해 제어 가능한 메모리 예산을 지원하기 때문에 두
가지 유형의 타일 사이에 내부적 차이가 있습니다. 이 예산은 4바이트 요소의
수로 지정됩니다. 모든 매크로 타일에는 고정된 수의 4바이트 요소가
필요합니다. 즉, 총 매크로 타일 수가 메모리 예산에 따라 달라집니다.

매크로 타일의 크기는 간접 참조 버퍼에서 픽셀 좌표의 순서도 제어합니다.
매크로 타일의 크기가 클수록 순서가 약해집니다. 예를 들어, 매크로 타일의
크기가 전체 이미지의 크기보다 크거나 같으면 동일한 마이크로 타일에서
오는 동일한 ID를 가진 픽셀 그룹의 위치는 최종 시퀀스 내에서 결정되지
않습니다. 반면에 매크로 타일이 마이크로 타일과 크기가 같으면 픽셀 그룹은
최종 시퀀스 내에서 결정적 위치를 갖습니다. 동일한 마이크로 타일의 픽셀
좌표는 항상 메모리에 인접하게 저장되지만 마이크로 타일 내의 순서도
결정적이지 않습니다.

# 구현 참고 사항

픽셀 비닝, 관련 시각화 및 정확성 테스트를 수행하는 모든 코드는 다음 두
파일에 있습니다. *PixelBinner.h/.cpp* 이러한 파일은 작은 드롭인
라이브러리를 형성합니다. *PixelBinner.h*에는 제공된 pixelBinner\* API를
사용하는 방법에 대한 광범위한 문서가 포함되어 있습니다.

샘플에는 여러 단계가 포함되어 있습니다. 첫 번째 단계는 픽셀 ID를
출력하는 데 사용되는 2d 심플렉스 노이즈 (Quilez, 2013)를 생성합니다. 두
번째 단계는 여러 컴퓨팅 커널을 디스패치하여 작동하는 비닝 패스 자체(또는
부분 정렬)입니다.

첫 번째 커널은 선택한 스레드 그룹의 크기에 따라 64x32 또는 64x64 픽셀
크기의 단일 *마이크로 타일*을 처리하는 512/1024 크기 스레드의 스레드
그룹으로 구성됩니다. 이 커널은 처리된 마이크로 타일 내에서 지정된 범위의
모든 ID와 연결된 픽셀 수를 계산합니다. 지원되는 가장 넓은 ID 범위는
\[0:2047\]입니다. 이러한 스레드 그룹이 완료되기 직전에 매크로 타일당 각
ID별로 전역 카운터를 증가시킵니다.

다음 하나 또는 두 개의 커널(매크로 타일 수에 따라 다름)은 첫 번째 커널이
작성한 카운터의 전역 배타적 접두사 합계를 계산합니다.

마지막 커널은 첫 번째 커널과 동일한 작업 세트로 시작하지만 전역 접두사
합계를 가져온 후 간접 참조 버퍼의 적절한 위치에 픽셀 좌표를 씁니다. 이
단계는 비닝 패스를 완료합니다. 픽셀 좌표를 포함하는 간접 참조 버퍼는 이
단계가 완료되면 사용할 준비가 된 것입니다.

*ExecuteIndirect*에 대한 인수 버퍼를 출력하는 선택적 커널도 있습니다. 이
커널은 *전역* 비닝에만 사용됩니다. 모든 id에 대해 간접 디스패치 인수와
루트 상수를 계산합니다.

이것은 모든 id에 대해 고유한 셰이더를 디스패치할 기회를 제공합니다.

비닝 패스가 완료된 후 몇 가지 선택적 시각화 패스와 정확성 검사를
수행하는 패스가 있습니다. 후자는 샘플의 렌더링 루프를 완료합니다.

# 알려진 문제
