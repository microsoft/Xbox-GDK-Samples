#   VRS 和稀疏照明示例

*此示例兼容于 Microsoft 游戏开发工具包（2020 年 8 月）*

# 

# 说明

此示例包含一个更优化的着色器，用于生成 VRS 着色率映像，而不是上一个 VRS
示例。

此示例实现稀疏延迟照明。它使用 VRS 呈现 g
缓冲区。然后，构建一个像素缓冲区以使其变亮，从而避免从同一三角形和具有相同
g
缓冲区值的照明相邻像素的冗余。此像素子集已亮起，并且值以水平、垂直或对角线方式被复制。此示例演示了
VRS 和稀疏照明可以显著 节省 GPU。

此示例提供了两种不同的方法来计算像素到光的子集，使用压缩深度平面方程或使用
SV_Coverage 和 SV_ShadingRate。后一种方法需要 4 位 g
缓冲区空间，并且对于"扩展"深度磁贴或电脑是必需的。

此示例演示了减少延迟照明通道中所需的波总数，显著成本是光线行进柔影。可以使用相同的技术和缓冲区（包括稀疏
SSR、SSAO、SSGI、屏幕空间阴影掩码、雾等）进行其他稀疏传递。此示例实现了"旋转"每帧点亮的像素。与
TAA 结合使用时，这可能非常有用，可以根据事实进行聚合。

最后，该示例演示了"deblocking"，这是一种将"VRS
平方"作为后期进程删除的方法。

# 实施说明

屏幕分为 16x16 个磁贴，每个磁贴都有一个计数（纹理中的 R8
条目）和每个磁贴最多 224 个有效负载数据。有效负载 dword 包含一个磁贴相对
x/y 坐标，每个坐标 4 位，21 位无序深度和 3
位，用于是水平、垂直还是对角复制照明计算的最终结果。如果磁贴中的照明计算数大于
224，则没有 wave32 可以提前输出，因此所有 256 像素都以传统方式亮起。

分派足够的波来照亮每个像素，波形由于像素计数减少而立即到达磁贴上时，就会获得成功。每个波的工作流程像素都在同一个
16x16 图块内，意味着光源列表仍然是波形的标量，这是一个重要的优化。

通过在着色器的开头调用稀疏照明 Prefix84 并在着色器结束时调用稀疏照明
Postfix，可以对延迟照明着色器进行简单的修改以支持稀疏照明。

最关注的着色器可能包括：

1.  GenerateShadingRateCS.hlsl

2.  DepthjDecompressAndBuildSparseBuffersCS.hlsl

3.  SparseLightingCommon.hlsli

4.  LightingShader.hlsli

5.  Deblock.hlsli

6.  稀疏照明显示 PixelCopiesCS.hls 作为调试着色器也可能很有趣

此示例还实现了深度解压缩计算机着色器，该着色器采用压缩的反向 Z
并输出线性正向 Z，请参阅 DepthDecompress.hlsl

# 已知问题

在某些情况下，着色率的确定在时间上不稳定，并且通过后去块过程删除 VRS
方块可能会使情况变得更糟。通常，TAA
会聚合在基本事实之上，隐藏这种轻微的不稳定性，但该示例没有 TAA 实现。
