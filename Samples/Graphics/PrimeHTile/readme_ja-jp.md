# PrimeHTile サンプル

*このサンプルは、Microsoft Game Development Kit と互換性があります (2022 年 3 月)*

# 説明

このサンプルでは、深度値を持つ HTile の HiZ 部分の準備について示します。これにより後続のレンダリングでピクセル シェーディング前の深度テストの失敗が有効になります。 これは、オクルージョン カリング用の CPU ラスター化された深度バッファーが既にあるタイトルに特に関連しており、GPU の高速化に同じデータを使用できるようにします。 これは、g バッファーのレイアウトダウン中に過剰に取り出されるのを減らすのに役立ちますが、Forward+ を使用するタイトルでは特に重要な場合があります。これにより、各ピクセルが過剰に引き出されるごとに、より大きなペナルティが発生します。

このサンプルでは、CPU ラスタライズ深度を使用する代わりに、GPU を使用して、HTile の解像度で深度をレンダリングし、GPU 時間を全体的に節約します。

このサンプルでは、ピクセル シェーダーの制限と頂点シェーダーの制限の間で負荷を変更できるように、キューブの一部をレンダリングします。 また、視差マッピングを実装し、ユーザーがピクセル シェーディングのコストの影響を示すために、このマッピングとぶつかりのマッピングを切り替えることができます。

# 実装メモ

HTile は、8x8 タイルあたりの最小深度と最大深度を格納します。 プリピクセル シェーダー深度カリングを有効にすると、各三角形は HTile の解像度で粗くラスター化されます。 遠くの深さを超えるフラグメントはカリングされ、近い深度よりも近いフラグメントは簡単に受け入れられ、HTile の近い深度と遠い深度の範囲にあるフラグメントは、完全な解像度深度テストを受ける必要があります。

このサンプルでは、GPU を使用して、HTile の解像度 (\~1/8 番目の完全解像度) でオクルージョン バッファーをレンダリングし、これらの深度を HTile に書き込みます。 深度バッファーと HTile スウィズリングが異なるので、スウィズリングは HTile プリミティブ シェーダーによってソフトウェアで行われます。 HTile のプライミングは CPU によって実行できますが、通常は HTile を ESRAM に含めたい場合があるため、コピー操作が必要です。

この手法は、従来の深度プリパスと組み合わせることができます。 例:

1. HTile 解像度深度バッファーをバインドする

a.   レンダー フィルの制限付きオキュラー (建物のスラブ側など)

2. 完全な解像度の深度をバインドする

a.   オクルージョン バッファーを使用した HTile の素数

b.   頂点の制限付きオクルーダー (プレイヤーの車など) をレンダリングする

事前に生成された深度バッファー、ソフトウェア、またはハードウェアラスター化された深度値は 1 つだけであり、範囲は生成されません。 したがって、唯一の有効なオプションは、HTile の近深度と遠距離深度の両方を同じ値に設定する方法です。 ただし、この値は、後でレンダリングされるジオメトリを正しく表すとは限りません。 この問題はシャドウ アクネに似ていますが、サンプリング中はピクセルが誤って拒否されることを意味します。 このサンプルでは、この問題に対処するための 3 つの異なる方法を示しています。それぞれの方法を組み合わせて使用できます。

1. 深度エンコードに整数バイアスを追加する

2. オクルージョン ジオメトリを縮小して保守的にする

3. HTile エンコード中に、最大 3x3 の深度値を取得します。 (これは非常に効果的です)

これらの方法のいずれも独自に完全な修正を提供しませんが、十分な結果が見つかります。 メソッドによってパフォーマンスのトレードオフが異なります。

HTile のプリミティブ化により、GPU で深度圧縮を使用できなくなります。ただし、オーバー描画の削減は、この損失をオフセットする以上に大きくする必要があります。 余談ですが、HTile が準備された深度バッファーをクリアする必要はありません。これは無料です。

グラフィックス エンジンや CPU を使用して隠れた深度バッファーをレンダリングする代わりに、タイトルで非同期コンピューティングを使用することが必要になる場合があります。 「<https://github.com/jbarczak/CSRasterization>」を参照してください。

このサンプルは、DirectX 12.X を使用して実装されています。 ルート シグネチャを削除すると、DirectX 11.X の実装に同じシェーダー (PrimeHTileCS.hlsl) を使用できます。

# プライバシーに関する声明

サンプルをコンパイルして実行する場合、サンプルの使用状況を追跡するために、サンプルの実行可能ファイルのファイル名が Microsoft に送信されます。 このデータ コレクションからオプトアウトするには、Main.cpp の "サンプル使用状況テレメトリ" というラベルの付いたコードのブロックを削除します。

Microsoft のプライバシー ポリシー全般の詳細については、「[Microsoft のプライバシーに関する声明](https://privacy.microsoft.com/en-us/privacystatement/)」を参照してください。
