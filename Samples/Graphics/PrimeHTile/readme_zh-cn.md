# PrimeHTile 示例

*此示例可用于 Microsoft 游戏开发工具包（2022 年 3 月）*

# 说明

此示例演示了如何使用深度值启动 HTile 的 HiZ 部分，从而使后续渲染无法实现深度测试预像素着色。 这尤其适用于已具有用于遮蔽剔除的 CPU 栅格深度缓冲区的游戏，从而使相同的数据可用于加快 GPU 速度。 这对于减少 g 缓冲区布局期间的过度透支非常有用，但是使用 Forward+ 的游戏可能特别感兴趣，因为使用 Forward+ 会对每个像素过度透支产生较重的损失。

该示例未使用 CPU 栅格深度，而是使用 GPU 以 HTile 的分辨率渲染深度，整体上还会节省 GPU 时间。

该示例呈现多维数据集的分组，允许用户在像素着色器受限和顶点着色器受限之间改变负载。 它还实现视差映射，并允许用户在此映射和凹凸映射之间切换，以显示像素着色费用的效果。

# 实现说明

HTile 存储每 8x8 磁贴的最小和最大深度。 启用前像素着色器深度剔除时，每个三角形都会以 HTile 分辨率粗糙地光栅化。 将剔除超出远深度的任何片段，任何接近近深度的片段都通常会被接受，并且位于 HTile 近深度和远深度之间的任何片段都必须进行全分辨率深度测试。

该示例使用 GPU 以 HTile 的分辨率（\~1/8 全分辨率）呈现遮挡缓冲区，并将这些深度写入 HTile。 由于深度缓冲区和 HTile 重排不同，因此重排由 HTile 启动着色器在软件中完成。 HTile 启动可由 CPU 完成，尽管通常 HTile 可能希望位于 ESRAM 中，因此仍需要执行复制操作。

该技术可以与传统的深度预传结合使用。 例如:

1. 绑定 HTile 解析深度缓冲区

a.  渲染填充受限遮挡器（例如建筑物的碎片边）

2. 绑定全分辨率深度

a.  使用遮挡缓冲区的 Prime HTile

b.  呈现顶点受限遮挡器（例如玩家的车）

预生成的深度缓冲区、软件或硬件光栅化只具有单个深度值，且不生成范围。 因此，唯一合理的选择是将 HTile 的近深度和远深度设置为相同的值。 但是，此值不一定正确地表示稍后将呈现的几何图形。 此问题在一定程度上类似于阴影声，在采样下表示像素被错误地拒绝。 此示例演示了解决此问题的三种不同方法，每个方法可以结合使用：

1. 向深度编码添加整数偏差

2. 通过收缩遮挡几何图形，使其变得保守

3. 在 HTile 编码期间，采用 3x3 深度值的最大值。 （这非常有效）

这些方法本身都不提供完美的修补程序，但可以找到令人满意的结果。 不同的方法有不同的性能权衡。

HTile 启动可防止 GPU 使用深度压缩，但覆盖量的减少应大于偏移此损失的偏移量。 另一方面，无需清除任何具有 HTile 准备的深度缓冲区，这是免费的。

游戏可能希望使用异步计算，而不是使用图形引擎或 CPU 来呈现 occluding 深度缓冲区。 请参阅 <https://github.com/jbarczak/CSRasterization>。

此示例使用 DirectX 12.X 实现。 如果删除根签名，则可以将相同的着色器 （PrimeHTileCS.hlsl） 用于 DirectX 11.X 实现。
