#   动态分辨率示例

*此示例兼容于 Microsoft 游戏开发工具包（2020 年 6 月）。它当前不支持
Xbox One X 主机模式。*

# 

# 说明

此示例演示了如何通过调制分辨率来响应不断变化的性能条件，从而维持帧速率。

# ![](./media/image3.jpeg)

# 生成示例

如果使用 Project Scarlett，请将活动解决方案平台设置为
Gaming.Xbox.Scarlett.x64。

如果使用 Xbox One 开发工具包，请将活动解决方案平台设置为
Gaming.Xbox.XboxOne.x64。

*有关详细信息，请参阅位于 GDK 文档中的* Running samples*，。*

# 实现说明

## 算法

该示例的目标是做出三个决定：

1.  在当前分辨率下，游戏是否会在不久的将来丢帧？

2.  降低分辨率是否有助于避免丢帧（即性能是否受到 GPU 负载限制）？

3.  游戏能否以更高的分辨率保持帧率？

为了测试此目标，该示例生成了许多综合方案，旨在模拟游戏中不同类型的帧速率不稳定情况：

1.  GPU 负载瞬时峰值

2.  GPU 负载长时间溢出

3.  CPU 负载长时间溢出

这些方案的所需结果（分别）为：

1.  降低分辨率，然后在峰值通过后提高分辨率

2.  将分辨率降低到维护帧速率所需的最小量

3.  不执行任何操作（分辨率不会影响 CPU 负载）

示例的核心算法驻留在函数 **Sample::DetermineResolution**
中。示例中的许多其他代码都专用于帧速率模拟以及仔细测量和绘图。在游戏引擎中实现动态分辨率时，不需要移植后一个代码。

该示例在相机处于运动状态之前等待修改分辨率。分辨率更改在静态场景中十分明显，但在移动场景中通常无法察觉。因此，最好让固定元素（如
UI）保持固定的分辨率。该示例通过将主场景呈现到背景显示平面，并将 UI
元素呈现到前景显示平面来实现此目标。背景平面支持动态更改分辨率以响应处理器负载。前景平面以固定分辨率
1920x1080 呈现。

建议在可能的情况下，游戏保持固定的垂直分辨率，并且仅降低水平分辨率。此建议的原因有两个：

1.  硬件缩放器在 x 方向上的点击数多于 y
    方向的点击数，因此可以更好地在水平方向上扩展。

2.  大多数游戏运动（相机和对象）倾向于采用 x
    方向，因此水平分辨率不太明显。

## 别名呈现目标

为了在不增加内存使用率的情况下允许任意数量的分辨率，该示例将所有场景呈现和深度目标分别以别名设置到同一内存中。例如，当示例启动时，它会创建一个
1920x1080 呈现器目标。如果分辨率更改为
1728x1080，则会在原始呈现目标所在的内存分配处创建新的*放置资源*。在分辨率再次更改之前，该资源将用作新的较小的呈现器目标。由于一次只有一个分辨率处于活动状态，因此
1920x1080 和 1728x1080
呈现器目标可以共享内存，而不会发生冲突。深度目标的工作方式与之相同。

**ResolutionData** 结构保留需要以特定分辨率呈现的资源（描述符句柄和 D3D
资源）。**ResolutionSet** 类管理一组 ResolutionData
结构，并负责在分辨率更改时根据需要创建新的放置资源。该示例仅使用单个
ResolutionSet
来呈现其场景，但如果游戏具有多个呈现器目标（例如在延迟的呈现器中），则可以使用多个。

请注意，该示例执行从其当前呈现器目标到固定大小交换链左上角的纹理复制。这只是因为该示例足够简单，只需一次传递即可呈现所有内容。在真实游戏中，最终的全屏传递可以直接呈现到交换链的左上角。在任一情况下，调用
ID3D12CommandQueue::PresentX 时将使用
D3D12XBOX_PRESENT_PLANE_PARAMETERS::pSrcViewRects
来指示要显示交换链的哪个部分。

## 分析结果

该示例绘制了多个图形和指示器，以帮助即时和随时间推移分析性能：

**图形：**

-   像素计数 (%) - 总像素相对于理想分辨率 1920x1080 的百分比。

-   帧时间（毫秒）-
    交换链的连续"翻转"之间的时间。在此图中，单个已删除帧将显示为峰值。

-   Vsync 裕量（毫秒）-
    帧准备就绪和计划显示之间的时间。单个已删除帧将导致此图低于 0
    毫秒基线。

**指标：**

-   平均 FPS - 滑动窗口上的平均帧速率。

-   撕裂 - 撕裂发生（滞后几帧）时屏幕上的垂直点。屏幕顶部表示无撕裂。

要了解动态分辨率方法如何影响观察到的性能，请观察两个指标几秒钟，然后使用
B
按钮打开/关闭该方法。你还可以专注于旋转场景，并尝试直接挑选出撕裂和丢帧。

# 已知问题

此示例需要 2020 年 6 月 GDK 和恢复或更新的版本。

生成 Gaming.Xbox.XboxOne.x64
配置时，由于使用了多个显示平面，此示例将不会在 Xbox One X
主机模式下运行。可以通过将主机模式设置更改为 Xbox One 或 Xbox One S，在
Xbox One X 开发工具包上运行它。还可以在 Project Scarlett
开发工具包上运行 Gaming.Xbox.Scarlett.x64 配置。

在调试生成配置中运行示例时，额外的 CPU
开销可能会降低动态分辨率的有效性，尤其是在 Xbox One
主机模式下。在配置文件或版本配置中运行以获得最佳结果。

动态分辨率方法需要对每个游戏进行仔细优化。根据游戏的性能配置文件（包括典型和极端条件），可能需要向上或向下调整各种常量。

异常退出时，该示例可能显示为短暂挂起主机。此行为是由用于强制执行特定处理器负载进行试验的"wait"机制所导致的。动态分辨率方法不会在游戏中导致此类行为。
