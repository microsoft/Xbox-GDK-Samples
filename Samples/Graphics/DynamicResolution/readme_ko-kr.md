#   동적 해상도 샘플

*이 샘플은 Microsoft 게임 개발 키트(2020년 6월)와 호환됩니다. 현재 Xbox
One X 콘솔 모드를 지원하지 않습니다.*

# 

# 설명

이 샘플은 성능 조건 변화에 대응하여 해상도를 조절함으로써 프레임 속도를
유지하는 방법을 보여줍니다.

# ![](./media/image3.jpeg)

# 샘플 빌드

Project Scarlett를 사용하는 경우 활성 솔루션 플랫폼을
Gaming.Xbox.Scarlett.x64로 설정합니다.

Xbox One 개발 키트를 사용하는 경우 활성 솔루션 플랫폼을
Gaming.Xbox.XboxOne.x64로 설정합니다.

*자세한 내용은 GDK 설명서에서* 샘플 실행을 *참조하세요.*

# 샘플 사용

이 샘플에서는 다음 컨트롤을 사용합니다.

| 작업                                   |  게임 패드                   |
|----------------------------------------|-----------------------------|
| 화면 메뉴 탐색                         |  왼쪽 엄지스틱/방향 패드     |
| 동적 해상도 설정/해제                  |  Y 버튼                      |

# 구현 참고 사항

## 알고리즘

샘플의 목표는 다음 세 가지 결정을 내리는 것입니다.

1.  현재 해상도에서 타이틀은 앞으로 프레임을 삭제하나요?

2.  해상도를 줄이면 프레임 낙하를 방지할 수 있나요(예: GPU 부하로 인해
    성능이 제한됨)?

3.  타이틀이 프레임 속도를 더 높은 해상도로 유지할 수 있나요?

이 목표를 테스트하기 위해 샘플은 게임에서 다양한 종류의 프레임 속도
불안정성을 모델링하기 위한 여러 가상 시나리오를 생성합니다.

1.  GPU 부하의 일시적인 급증

2.  GPU 로드의 장시간 오버런

3.  CPU 로드의 장시간 오버런

이러한 시나리오에 대해 원하는 결과는 각각 다음과 같습니다.

1.  해상도를 줄인 다음, 스파이크 패스 후 해상도를 높입니다.

2.  프레임 속도를 유지하는 데 필요한 최소 크기만큼 해상도 줄이기

3.  아무 작업도 수행하지 않음(해상도는 CPU 부하에 영향을 주지 않음)

샘플의 핵심 알고리즘은 **Sample::D etermineResolution** 함수에 있습니다.
샘플의 다른 코드 대부분은 프레임 속도 시뮬레이션과 신중한 측정 및
그래프에만 적용됩니다. 게임 엔진에서 동적 해상도를 구현할 때는 후자의
코드를 이식할 필요가 없습니다.

샘플은 카메라가 동작할 때까지 해상도를 수정하기 위해 대기합니다. 해상도
변경은 정적 장면에서 눈에 띄지만 일반적으로 움직이는 장면에서는 눈에
띄지 않습니다. 이러한 이유로 고정된 해상도로 UI와 같은 고정 요소를
유지하는 것이 좋습니다. 샘플은 기본 장면을 배경 디스플레이 평면으로
렌더링하고 UI 요소를 전경 디스플레이 평면에 렌더링하여 이 목표를
달성합니다. 백그라운드 평면은 프로세서 부하에 대한 응답으로 동적으로
해상도 변경을 지원합니다. 포그라운드 평면은 1920x1080의 고정 해상도로
렌더링됩니다.

가능한 경우 타이틀은 고정 세로 해상도를 유지하고 가로 해상도만 줄이는
것이 좋습니다. 이 권장 사항의 이유는 다음 두 가지입니다.

1.  하드웨어 배율 조정기는 y 방향보다 x 방향에서 더 많은 탭을 사용하므로
    수평으로 업스케일링하는 더 나은 작업을 수행합니다.

2.  대부분의 게임 동작(카메라 및 개체)은 x 방향을 선호하는 경향이
    있으므로 가로 해상도는 눈에 띄지 않습니다.

## 별칭이 지정된 렌더링 대상

메모리 사용량을 늘리지 않고 임의의 수의 해상도를 허용하기 위해 샘플은
모든 장면 렌더링 및 깊이 대상을 각각 동일한 메모리에 별칭으로
지정합니다. 예를 들어 샘플이 시작되면 1920x1080 렌더링 대상을 만듭니다.
해상도가 1728x1080으로 변경되면 원래 렌더 대상과 동일한 메모리 할당에
*배치된 새 리소스*가 생성됩니다. 해상도가 다시 변경될 때까지 더 작은 새
렌더링 대상으로 사용됩니다. 한 번에 하나의 해상도만 활성화되므로
1920x1080 및 1728x1080 렌더링 대상은 충돌 없이 메모리를 공유할 수
있습니다. 깊이 대상은 동일한 방식으로 작동합니다.

**ResolutionData** 구조체는 특정 해상도에서 렌더링하는 데 필요한
리소스(설명자 핸들 및 D3D 리소스)를 포함합니다. **ResolutionSet**
클래스는 ResolutionData 구조체 집합을 관리하며, 필요한 경우 해결 방법이
변경될 때 배치된 새 리소스를 만듭니다. 샘플에서는 단일 ResolutionSet만
사용하여 장면을 렌더링하지만, 지연된 렌더러와 같이 렌더링 대상이 여러 개
있는 경우 게임에서 둘 이상을 사용할 수 있습니다.

샘플은 현재 렌더링 대상에서 고정 크기 스왑 체인의 왼쪽 상단 모서리로
텍스처 복사를 수행합니다. 이는 샘플이 모든 항목을 한 패스로 렌더링할
만큼 간단하기 때문입니다. 실제 게임에서 최종 전체 화면 패스는 스왑
체인의 왼쪽 위에 직접 렌더링할 수 있습니다. 두 경우 모두
ID3D12CommandQueue::P resentX를 호출할 때
D3D12XBOX_PRESENT_PLANE_PARAMETERS::p SrcViewRects를 사용하여 표시할
스왑 체인의 일부를 나타냅니다.

## 결과 분석

이 샘플은 몇 가지 그래프와 지표를 그려서 시간 경과에 따라 즉시 성능을
분석하는 데 도움이 됩니다.

**그래프:**

-   픽셀 수(%) -- 1920x1080의 이상적인 해상도를 기준으로 하는 총 픽셀의
    백분율입니다.

-   프레임 시간(밀리초) -- 연속된 \'대칭 이동\' 사이의 시간 스왑 체인의
    입니다. 삭제된 개별 프레임이 이 그래프에서 급증으로 표시됩니다.

-   Vsync 여백(ms) -- 프레임이 준비되었을 때와 표시되도록 예약된 시간
    사이의 시간입니다. 개별 프레임이 삭제되면 이 그래프가 0ms 기준선
    아래로 떨어집니다.

**표시기:**

-   평균 FPS -- 슬라이딩 윈도우의 평균 프레임 속도입니다.

-   찢어짐 -- 찢어짐이 발생한 화면의 수직 지점입니다(몇 가지 프레임만큼
    지연). 화면 위쪽은 깨지지 않음을 나타냅니다.

동적 해상도 메서드가 관찰된 성능에 미치는 영향을 이해하려면 몇 초 동안
두 지표를 확인한 다음 B 단추를 사용하여 메서드를 켜거나 끕니다. 회전하는
장면에 초점을 맞추고, 회전 및 삭제된 프레임을 직접 선택하려고 할 수도
있습니다.

# 알려진 문제

이 샘플에는 2020년 6월 GDK 및 복구 또는 최신 버전이 필요합니다.

Gaming.Xbox.XboxOne.x64 구성을 빌드할 때 이 샘플은 여러 디스플레이
평면을 사용하기 때문에 Xbox One X 콘솔 모드에서 실행되지 않습니다. 콘솔
모드 설정을 Xbox One 또는 Xbox One S 변경하여 Xbox One X 개발 키트에서
실행할 수 있습니다. Project Scarlett 개발 키트에서
Gaming.Xbox.Scarlett.x64 구성을 실행할 수도 있습니다.

디버그 빌드 구성에서 샘플을 실행할 때 추가 CPU 오버헤드로 인해 특히 Xbox
One 콘솔 모드에서 동적 해상도의 효율성이 떨어질 수 있습니다. 최상의
결과를 얻으려면 프로필 또는 릴리스 구성에서 실행합니다.

동적 해상도 방법을 사용하려면 각 타이틀에 대해 신중하게 조정해야 합니다.
일반적인 조건과 극단적인 조건을 포함하여 타이틀의 성능 프로필에 따라
다양한 상수가 위 또는 아래로 조정되어야 할 수 있습니다.

샘플은 비정상적인 종료 시 콘솔을 잠시 중단하는 것처럼 보일 수 있습니다.
이 동작은 \'wait\'로 인해 발생합니다. 실험을 위해 특정 프로세서 로드를
적용하는 데 사용되는 메커니즘입니다. 동적 해상도 방법은 게임에서 이러한
동작을 일으키지 않습니다.
