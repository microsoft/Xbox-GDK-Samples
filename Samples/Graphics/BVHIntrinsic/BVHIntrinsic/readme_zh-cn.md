# 实现说明

## 三角形/龙场景

适用于 7 个 LOD 的 BVH 演示是使用 Intel Embree 的 BVH 生成器 C++ API 构建的。 生成后，用于从硬件不可知的硬件转换 BVH 的传递
已执行 FP16 AABB 和三角形。 追加到缓冲区末尾的是一个 DWORD，指示模型中有多少个三角形。 文件中的前 64 个字节表示 BVH 的&ldquo;根节点&rdquo;。 着色器&ldquo;RaytraceTriangles.hlsl&rdquo;负责遍历从根节点到最终三角形命中或未命中的 BVH。 此计算着色器维护每个线程 28 个 DWORD 的小堆栈，以便在树中存储将来的潜在节点，以便在以后进行跟踪。 数字&ldquo;28&rdquo;是通过观察演示中使用的内容实验得出的。 通过将堆栈大小保持尽可能小，我们最大程度地提高了 CU/WGP 上运行的波形数，因为 LDS 的使用是占用率较高的限制因素。

核心遍历循环看似简单，并执行以下步骤:

1) 将光线与遍历循环中的下一个节点相交(最初是根节点)

2) 如果此节点是三角形节点:

a.  计算与命中的&ldquo;t&rdquo;距离(如果错过，则&ldquo;t&rdquo;为&ldquo;无穷大&rdquo;)。

b.  确定此命中是否比上一次最接近的命中更近。

i.  如果是这样，请更新命中距离、最近的节点指针和三角形 ID

ii. 如果没有，则不执行任何操作

c.  将下一个节点指针设置为 InvalidNodePtr，以便我们在步骤 4 中弹出堆栈中的一个指针。

3) 如果此节点是 FP16 AABB 节点:

a.  将最接近的 AABB 命中 (childPtrs.x) 设置为我们关注的下一个节点，无论是否有效。

b.  对于其他 3 个 AABB，请按反向距离顺序推送到堆栈(如果有效)。

4) 如果我们在循环的下一次迭代中没有要遵循的其它节点...

a.  如果堆栈可用，从堆栈中弹出一个

5) 如果下一步仍然没有另一个节点，遍历将立即终止。

结构化返回的 RaytraceResults 包含有关命中的信息:

- &ldquo;hit&rdquo; - 是否命中了三角形。

- &ldquo;leafIndex&rdquo; - 唯一标识命中来自哪个三角形**节点**的索引

- &ldquo;nearestT&rdquo;-- 到最接近命中的命中距离，如果没有命中，则为无穷大。

- &ldquo;numIterations&rdquo; -- 光线完成 BVH 的上下步骤数

- &ldquo;triIndexInLeaf&rdquo; -- 0-3，具体取决于我们命中叶中的三角形索引

由于此 BVH 包含重叠的 AABB，因此在第一次命中时停止遍历并假定它是此光线最接近的可能命中数是不够的。 因此，当找到新的&ldquo;最接近命中&rdquo;时，我们会将&ldquo;nearestT&rdquo;更新到此距离。 &ldquo;nearestT&rdquo;作为我们想要查找命中数的新最大距离传递到 BVH 内部函数。 由于我们已确认命中，因此不再关注距离大于此距离的命中。

LOD0 模型包含近 500 万个多边形，表示的模型细化远远超出正常游戏内容的细化。 LOD1-6，从 200,000 个多边形开始，每个 LOD 减少一半，对于现代视频游戏来说，内容级别要合理得多。 BVH 的大小在 266MB 和 0.3MB 之间变化。

四种可视化模式分别是:

- 正常 -- 此模式只需为每个三角形分配一个唯一索引，然后生成灰度颜色，即可将其可视化。

- 深度 -- 反向 Z 线性深度值。

- 遍历成本 -- 光线复杂性的&ldquo;热度地图&rdquo;。 光线命中(或错过)其目标所执行的步骤越多，像素越亮。 与穿过自由空间或正面影响模型的光线相比，接近表面的光线需要更多的迭代。

- 基元 -- 根据&ldquo;leafIndex&rdquo;进行简单着色。 由于三角形可以存储在一组 1-4 个三角形中(在三角形节点中)，因此，了解这些三角形的存储方式可能很有趣。

[体素 / Kescha 的 Rungholt](https://www.planetminecraft.com/project/rungholt-3505409/)

体素场景由在线提供的 Rungholt 数据集中的 1670 万个体素组成。 与 Dragon 数据集一样，此模型使用 Intel 的 Embree BVH 生成器生成，并转换为
可用。 此 BVH 与其他场景不同，因为将体素视为树中的&ldquo;叶&rdquo;类型 -- 这意味着在 BVH 中不存储任何三角形。 BVH 的上层存储方式与三角形场景中的存储方式相同，但叶节点中的&ldquo;子级指针&rdquo;具有保留位，以指示它们实际上是叶，不需要进一步遍历(位 30，0x40000000)。 低 30 位编码刚刚命中的 AABB 的位置(以 `11_8_11` - XYZ 格式存储) -- 允许最大大小为 2048 x 256 x 2048 的数据集。

将此信息存储在子节点指针本身的优点是，无需将辅助数据结构与 BVH 一起存储。 此信息由 BVH 内部函数直接返回给我们，无需执行其他加载操作。

与三角形 BVH 相比，此 BVH 在单个 AABB 节点中不包含重叠的 AAB。 通过此保证，我们可以在第一次遇到问题时终止遍历，不必担心 LDS 堆栈中可能存在更接近的命中。 出于此原因，遍历例程 (RaytraceVoxels.hlsl) 比三角形例程更简单。

但是，在找到第一个(和最近的)命中后，BVH 内部函数将不提供有关命中距离或 AABB 本身发生命中的任何坐标的信息。 我们拥有的唯一信息是命中了哪个块。 出于此原因，在 ALU (AABBIntersect) 中执行了一个附加步骤，可帮助确定我们击中 AABB 的哪一侧和距离。 这两条信息就足以为体素提供光照和阴影。 如果想对体素进行纹理处理，将&ldquo;光线末端&rdquo;位置转化为纹理坐标是非常简单的。

然后，该样本继续每像素再发射三束光线。 这些光线包括:

1) 用于直接照明的简单定向阴影光线。

2) 水和玻璃表面的反射光线。

3) 阴影反射光线，用于确定反射表面上的直接照明。

不需要函数调用或递归，它只是一个迭代过程，将来可以扩展到环境遮挡、折射或全局照明，如果需要，无需进一步传递。

包含每个块&ldquo;ID&rdquo;(一个字节)的单独辅助结构指示我们命中的块类型。 由于在使用子指针存储&ldquo;块位置&rdquo;时，FP16 AABB 节点中没有可用的备用位，因此必须根据从 BVH 中的位置派生的索引从缓冲区中提取。
