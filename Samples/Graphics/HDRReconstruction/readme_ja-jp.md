# HDR 再構築のサンプル

*このサンプルは、Microsoft Game Development Kit と互換性があります (2022 年 3 月)*

# 説明

この例では、単純な後処理手法として、既にトーンマップされている SDR イメージから HDR を再構築する方法を示します。 この手法が便利なのは、レンダリング パイプラインを中断することがなく HDR をゲームに追加する、およびトーンマップ イメージと同じアート効果目的を維持するときです。さらにこの手法は SDR ビデオや UI スプラッシュ スクリーンにも適用できます。 サンプルでは、SDR と再構築した HDR を切り替えて、違いを簡単に比較できます。

![](./media/image1.jpeg)

HDR に関する課題の 1 つは、ビデオと UI スプラッシュ画面は、ほとんどが SDR として保存され、実際にレンダリングされたシーンと比較してくすく見えるということです。 この手法は、SDR コンテンツが自動的に HDR できる場合があります。 もう 1 つの課題は、HDR シーンの値を保持するためにゲームのトーンマップ 演算子を削除するだけで、特にトーンマップ 演算子がカラー 採点、明るさ、コントラストなどの操作と組み合わされている場合に、画像のアートの意図が失われる可能性があるということです。 適切な短期的な解決策は、逆トーンマッパーを使用して、ゲームの既にトーンマップされたカラー グレードの最終画像から HDR シーン値を再構築し、SDR イメージのアートな意図を維持することです。 これは SDR マスターと呼ばれます。HDR を HDR マスターイメージとして利用することはできませんが、ゲームが既に出荷されている優れた短期的なソリューションです。

長所

- SDR マスター(つまり、SDR アートインテントは HDR で同じままです)

- 後処理は、カラー 採点、トーン マッピング、AA などは、同じままです

- シーン ビデオの切り取りは同じままです

- 単一の後処理手法として簡単に実装

短所

- 白い外観に近い色 (例: 霧、パーティクル)

- フィルムグレインのようなノイズが強調される

- 精度の損失、FP11:11:10 -> 10:10:10:2

- HDR マスターほど良くはありません

注: このサンプルでは、いくつかの 8 ビット圧縮 SDR イメージを使用して結果を表示するため、圧縮アーティファクトとバンディングが表示される可能性があります。これは HDR 再構築手法では発生しません。

Xfest 2017 プレゼンテーション \"[HDR Tips and Tricks from the Tricks from the Trickses](http://aka.ms/XF17022)\" を参照してください。

このサンプルで使用されている画像は、このサンプル デモで使用するために <https://www.halowaypoint.com/en-us> と <https://gearsofwar.com/en-US/> から取得されたものです

# 実装メモ

このサンプルでは、ゲームの最終的なトーンマップ済み SDR バックバッファーをシミュレートするには、SDR トーンマップテクスチャをバックバッファーにレンダリングします。 これらのイメージは 8 ビット圧縮されているため、HDR 再構築手法によって発生しない圧縮アーティファクトとバンディングがサンプルに表示される場合があることに注意してください。

Reinhard に基づく単純な逆トーンマッパーを使用して HDR 値を再構築し、さらにオフセットとスケールを追加して曲線を曲げ、0.5 の値がホワイト ニトを返し、1.0f の値が指定された最大ニト値 (1000 ニトなど) を返すようにします。 Xfest 2017 プレゼンテーション [現場からの HDR のヒントとテクニック](http://aka.ms/XF17022) のスライド 12 - 15 を参照してください。 HDR 値は、輝度またはカラー チャネルごとに逆トーンマッパーを適用することで再構築できます。 (前方の) トーンマッパーと同様に、輝度ごとに使用すると正しい結果が得られますが、少し彩度を下げることもできます。 カラー チャネルごとの使用は飽和状態になりますが、カラー シフトが発生する可能性があります。 2 つの結果間の補間は、再構築された値の色の彩度を簡単に制御する方法です。

このサンプルでは、最終的なトーンマップされた SDR イメージの上に UI がレンダリングされます。つまり、白いテキストはトーンマップされた値と同じくらい明るい (1.0f、1.0f、1.0f) の値になります。 (1.0f、1.0f、1.0f) の値は最大ニト (1,000 ニトなど) に再構築されるため、白い UI テキストは明るくなりすぎてコンシューマーに大いに役立ちます。 そのため、線形スケールを計算して UI レンダリングを暗くし、再構築すると、白いテキストが 300 ニトなど、紙の白ニトと同じくらい明るくなります。

色域拡張は、Rec.709 色空間から P3 色空間に色を展開することによっても実装され、よりカラフルな画像になります。 SDR と HDR 範囲の色域拡張を分離し、2 つの間を補間します。 SDR の場合、完全な P3 色空間に拡張することはできません。これは、スキン トーンの変更が多すぎるため、Rec.709 よりも広く、P3 より小さいカスタム色空間を使用します。 HDR の場合は、完全な P3 色空間に拡張します。 これにより、色の彩度を明るく保つことができます。たとえば、明るい青い空は青のままで、色が明るくなるので色が失われません。

ピクセル シェーダーは、3D ルックアップ テーブル (SSD) を使用して簡単に最適化できます。
