# HDR 重建示例

*此示例可用于 Microsoft 游戏开发工具包 (2022 年 3 月)*

# 说明

此示例展示了如何通过简单的后处理技术，基于已进行音调映射的 SDR 图像重建 HDR。 该技术可用于在将 HDR 添加到游戏中而不中断渲染管道，同时保持与已音调映射的图像相同的艺术目的，并且还可以应用于 SDR 视频和 UI 初始屏幕。 该示例提供切换选项，可以轻松比较 SDR 和重建 HDR 之间的差异。

![](./media/image1.jpeg)

HDR 的一个挑战是视频和 UI 初始屏幕大部分都保存为 SDR，与实际呈现的场景相比，看起来很乏味。 此技术可以自动对 SDR 内容进行 HDR\'ify。 另一个挑战是，只需删除游戏的音调映射运算符以保留 HDR 场景值时，图像艺术意图可能会丢失，尤其是在音调图运算符与颜色评分、亮度和对比度等操作结合使用时。 一个不错的短期解决方案是使用反调映射器从游戏的已调色和彩色分级最终图像重新构造 HDR 场景值，从而保留 SDR 图像的艺术意图。 我们将其称为 SDR 主控映像，无法将 HDR 用作 HDR 主映像，但它仍然是一个不错的短期解决方案，游戏已随附。

优点

- SDR 已掌握，即 SDR 艺术意向对于 HDR 保持不变

- 后期处理保持不变，例如颜色评分、音调映射、AA

- 剪切场景视频保持不变

- 简单实现为单个后处理技术

缺点

- 接近白色外观的颜色，例如雾、粒子

- 像胶片粒度这样的噪音变得杂音

- 精度损失，FP11：11：10 -> 10：10：10：2

- 不如 HDR 主机

注意： 该示例使用多个 8 位压缩 SDR 映像来显示结果，因此压缩项目和带区可能可见，这不是由 HDR 重建技术引起的。

请参阅 Xfest 2017 演示文稿\&ldquo;[《天地](http://aka.ms/XF17022)中的 HDR 提示和技巧》\&rdquo;

此示例中使用的图像是从 <https://www.halowaypoint.com/en-us> 本示例演示中获取并 <https://gearsofwar.com/en-US/> 用于的

# 实现说明

在此示例中，通过将 SDR 音调映射纹理呈现到后台缓冲区来模拟游戏的最终音调映射 SDR 反向缓冲区。 请注意，这些图像是 8 位压缩的，因此你可能会在示例中看到压缩项目和带区，这不是由 HDR 重建技术引起的。

基于重新分片的简单反调映射器用于重新构造 HDR 值，并使用额外的偏移量和刻度来弯曲曲线，以便 0.5 的值返回白纸，而 1.0f 的值返回指定的最大 nits 值，例如 1000 nits。 请参阅 2017 年 Xfest 演示文稿 [的 12-15 张幻灯片 HDR 提示和](http://aka.ms/XF17022)技巧。 可以通过按亮度或按颜色通道应用反调映射器来重新构造 HDR 值。 与（正向）调色器类似，使用按亮度可提供正确的结果，但可能有点不饱和。 每个颜色通道的使用将更加饱和，但可能会出现颜色变化的情况。 在两个结果之间内插是控制重新构造值的颜色饱和度的简单方法。

在此示例中，UI 呈现在最终音调映射 SDR 图像的顶部，即白色文本的值 （1.0f， 1.0f， 1.0f）， 作为色调映射值， 与色调的太阳一样亮。 由于值（1.0f、1.0f、1.0f）重新构造为最大 nits（例如 1000 nit），因此白色 UI 文本对使用者而言会太亮和太粗。 因此，我们计算线性刻度以使 UI 呈现变暗，以便在重新构造时，白色文本将像纸白色 nits 一样亮，例如 300 尼特。

还可以通过将颜色从 Rec.709 颜色空间扩展到 P3 颜色空间来实现范围扩展，从而生成更彩色的图像。 我们分隔 SDR 和 HDR 范围的域扩展，然后在两者之间内插。 对于 SDR，无法扩展到完整的 P3 颜色空间，因为它会更改太多外观色调，因此我们使用比 Rec.709 宽但小于 P3 的自定义颜色空间。 对于 HDR，我们将扩展到完整的 P3 颜色空间。 这有助于保持亮度的颜色饱和度，例如，亮蓝色的天空仍将是蓝色的，并且不会丢失其变亮的颜色。

可以使用 3D 查找表 （LUT） 轻松优化像素着色器。
