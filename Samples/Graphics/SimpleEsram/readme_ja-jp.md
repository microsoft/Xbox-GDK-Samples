# シンプルな ESRAM サンプル

*このサンプルは、Microsoft Game Development Kit と互換性があります (2022 年 3 月)*

# 説明

このサンプルでは、DirectX 12 で ESRAM を使用する基本を示します。 XG および XGMemory API を使用して仮想リソース メモリを予約し、その後、DRAM と ESRAM にマップします。 いくつかのページ マッピング スキームが紹介されています。これは、DRAM と ESRAM の間のリソース レイアウトをカスタマイズするために XGMemory ライブラリを使用する方法の例です。

XG ライブラリには、DirectX で使用できるさまざまなリソースの種類のページ数を計算するための簡単なインターフェイスが用意されています。 DirectX リソースの実際のサイズ、レイアウト、配置、およびメタデータ構造は内部的に計算されるため、リソース サイズを正確に決定するために必要な手順です。これを使用してページ数を計算できます。 このページ数を使用して、ページ単位の粒度で ESRAM/DRAM マッピングを実行できます。

XGMemory ライブラリは、リソース ページを ESRAM メモリにマッピングするために推奨される方法です。 この API では、仮想アドレス空間の割り当てと物理メモリへのページのコミットに関する下位レベルの詳細が非表示になりますが、開発者はアドレス空間の各ページを DRAM または ESRAM にマップするかどうかを完全に制御できます。 また、安全で自由なリストページ割り当てスキームを利用し、危険な可能性のあるリソースエイリアスを明示的に実行することで、マップされたページの一貫性を内部的に管理します。

サンプルのメモリ マッピング スキームの簡単な概要:

> *単純なマッピング --* 指定された数のリソース ページを ESRAM にマップします
> 残りのページを DRAM に追加します。 この方法の利点は、
> 開発者による最小限の作業、1 回の関数呼び出しが必要ですが、
> カスタム動作を提供しません。
>
> *分割マッピング --* リソースを先頭の DRAM セクションに分割し、
> 中央の ESRAM セクションと末尾の DRAM セクション。 分割マッピングは、
> 低と低の両方をスポーツするレンダー ターゲットに役立つ
> 高い使用率を持つリージョンです。 たとえば、屋外シーンのレンダリング中
> 通常、skybox はフレームの上部を設定します。 この
> これらのピクセルに対する描画呼び出しは 1 つだけになります。これにより、メリットは少なくなります
> ESRAM 常駐から、発生する可能性があるイメージの残りの部分よりも
> 大幅に多くのオーバー描画が行えます。
>
> *メタデータ マッピング --* 色と深度のメタデータ テクスチャのみをマップし、
> ESRAM に追加します。 これは、最適化中に最小限の ESRAM を使用しているため、有益です
> クリアや解決などのメタデータの高速化された操作。
>
> *ランダム マッピング --* ランダム化されたページごとの DRAM または
> 指定した確率に従った ESRAM。 特定の情報はありません
> このマッピング スキームの利点は、単に
> 提供された API を一意の方法で提供します。

XG および XGMemory ライブラリの詳細と完全な API 仕様については、XDK ドキュメントを参照してください。

注: Xbox One Xには ESRAM がないため、より高速な DRAM でビルドされます。 このコンソールでは、ESRAM でのすべてのオプションと可視化機能が無効になった状況を、簡潔にレンダリングします。

# サンプルのビルド

Xbox One 開発キットを使用している場合は、アクティブなソリューション プラットフォームを `Gaming.Xbox.XboxOne.x64` に設定します。

ESRAM はサポートされていないため、このサンプルでは Gaming.Xbox.Scarlett.x64 はサポートされていません
このサンプルで使用されているのは、Gaming.Xbox.XboxOne.x64 とのみ互換性があります。 エミュレーションを使用して開発キットで実行されます。 *詳細については、**GDK ドキュメント*の「__サンプルの実行__」を参照してください。

# サンプルの使用方法

サンプルには、マッピング スキームを動的に切り替える機能を含む、プログラムのすべての状態に共通するコントロールがあります。 各マッピング スキームには、ゲームパッドのバンパーとトリガーを介して変更可能な独自のマッピング固有のパラメーターもあります。 これらのコントロールは、必要に応じて画面上にも表示されます。

## 共通コントロール

| 操作 | ゲームパッド |
|---|---|
| オービット カメラ | 左スティックと右スティック |
| マッピング スキームの切り替え | 方向パッド (左/右) |
| オーバーレイを切り替える | A ボタン |
| Exit | ビュー ボタン |

![](./media/image3.png)

## 単純なマッピング コントロール

| 操作 | ゲームパッド |
|---|---|
| カラー ESRAM ページ数を増やす | LB ボタン |
| カラー ESRAM ページ数を減らす | LT ボタン |
| 深度 ESRAM ページ数を増やす | RB ボタン |
| 深度 ESRAM ページ数を減らす | RT ボタン |

![](./media/image4.png)

## 分割マッピング コントロール

| 操作 | ゲームパッド |
|---|---|
| ESRAM 開始アドレスを増やす | LB ボタン |
| ESRAM 開始アドレスを減らす | LT ボタン |
| ESRAM 終了アドレスを増やす | RB ボタン |
| ESRAM 終了アドレスを減らす | RT ボタン |

## ![](./media/image5.png)

## メタデータ マッピング コントロール

| 操作 | ゲームパッド |
|---|---|
| オン/オフの切り替え | B ボタン |

## ![](./media/image3.png)

## ランダム マッピング コントロール

| 操作 | ゲームパッド |
|---|---|
| ESRAM ページの確率を下げる | LB ボタン |
| ESRAM ページの確率を上げる | RB ボタン |

# プライバシーに関する声明

サンプルをコンパイルして実行する場合、サンプルの使用状況を追跡するために、サンプルの実行可能ファイルのファイル名が Microsoft に送信されます。 このデータ コレクションからオプトアウトするには、Main.cpp の "サンプル使用状況テレメトリ" というラベルの付いたコードのブロックを削除します。

Microsoft のプライバシー ポリシー全般の詳細については、「[Microsoft のプライバシーに関する声明](https://privacy.microsoft.com/en-us/privacystatement/)」を参照してください。
