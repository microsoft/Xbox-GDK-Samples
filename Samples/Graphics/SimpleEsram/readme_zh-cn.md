# 简单 ESRAM 示例

*此示例可用于 Microsoft 游戏开发工具包 (2022 年 3 月)*

# 说明

此示例演示将 ESRAM 与 DirectX 12 配合使用的基础知识。 它使用 XG 和 XGMemory API 保留虚拟资源内存，随后将其映射到 DRAM 和 ESRAM。 显示有几种不同的页面映射方案可提供有关如何使用 XGMemory 库在 DRAM 和 ESRAM 之间自定义资源布局的示例。

XG 库提供了一个简单的界面，用于计算 DirectX 中可用的不同资源类型的页数。 由于 DirectX 资源的实际大小、布局、对齐方式和元数据结构是在内部计算，因此这是准确确定资源大小所必需的步骤，然后可以使用它来计算页计数。 然后，此页计数可用于按每页粒度执行 ESRAM/DRAM 映射。

建议使用 XGMemory 库将资源页映射到 ESRAM 内存。 此 API 隐藏分配虚拟地址空间并将其页面提交到物理内存的较低级别的详细信息，同时使开发人员能够完全控制地址空间的每一页是否映射到 DRAM 或 ESRAM。 它还通过使用安全的自由列表页面分配方案并强制显式执行潜在的危险资源别名，在内部管理映射的页面一致性。

示例的内存映射方案的快速概述：

> *简单映射 --* 将指定数量的资源页映射到 ESRAM
> 以及 DRAM 的剩余页面。 此方法的好处在于它
> 需要开发人员进行最少的工作、单个函数调用，但
> 不提供自定义行为。
>
> *拆分映射 --* 将资源拆分为开始的 DRAM 部分，
> 中间 ESRAM 部分和结束 DRAM 部分。 拆分映射可以
> 对同时显示低利用率和高利用率区域的
> 呈现目标是有益的。 例如，在室外场景呈现期间
> skybox 通常填充框架的顶部部分。 此
> 这将导致对这些像素只进行一次绘制调用，
> 这比图像的其他部分更少地受益于 ESRAM 驻留，
> 这可能会导致更多的过度绘制。
>
> *元数据映射 --* 仅映射颜色和深度元数据纹理
> 到 ESRAM。 这非常有用，因为它在优化时使用最小 ESRAM
> 元数据加速操作，如清除和解析。
>
> *随机映射 --* 执行 DRAM 或的随机每页选择
> 根据指定概率的 ESRAM。 此映射方案没有特定的
> 的优势 - 它只是展示了如何利用
> 以独特的方式提供的 API。

XDK 文档中提供了有关 XG 和 XGMemory 库的更多信息和完整 API 规范。

注意：Xbox One X 没有 ESRAM，而是使用更快的 DRAM 进行生成。 在主机上示例仅呈现禁用了所有 ESRAM 选项和可视化效果的场景。

# 生成示例

如果使用 Xbox One 开发工具包，请将活动解决方案平台设置为 `Gaming.Xbox.XboxOne.x64`。

此示例不支持 Gaming.Xbox.Scarlett.x64，因为此示例中使用的 ESRAM
仅与 Gaming.Xbox.XboxOne.x64 兼容。 它将使用仿真在开发工具上运行。 *有关更多信息，请参阅*&nbsp;__运行示例__（位于 *GDK&nbsp;文档）中。*

# 使用示例

该示例具有程序的所有状态通用的控件，其中包括在映射方案之间动态切换的功能。 每个映射方案还具有自己的特定于映射的参数，可通过游戏板缓冲键和触发器进行修改。 如果适用，这些控件在屏幕上也可见。

## 公共控件

| 操作 | 游戏板 |
|---|---|
| 旋转相机 | 左/右摇杆 |
| 切换映射方案 | 方向键向左键/向右键 |
| 切换覆盖 | A 按钮 |
| 退出 | &ldquo;视图&rdquo;按钮 |
