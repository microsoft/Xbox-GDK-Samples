#   带智能交付的流式安装示例

此示例与 Microsoft 游戏开发工具包（2020 年 2 月）兼容

#  

# 说明

此示例演示流式安装
API。安装启动区块后，可运行此示例来直观显示剩余区块的安装进度。

它还演示了智能安装功能，包括本地化区块、特定于硬件的区块和自定义标记。将根据目标硬件（Xbox
One 系列的 Durango/Xbox One X，Project Scarlett 系列的
Lockhart/Anaconda）的目标 SKU 和控制台的语言/区域设置，安装不同内容。

# 构建示例

如果使用 Xbox One 开发工具包，请将活动解决方案平台设置为
Gaming.Xbox.XboxOne.x64。

如果使用 Project Scarlett，请将活动解决方案平台设置为
Gaming.Xbox.Scarlett.x64。

有关详细信息，请参阅 GDK 文档中的"运行示例"。

# 使用示例

与大多数 GDK 示例不同，StreamingInstall 示例并不意味着要在 Visual Studio
中生成和部署。虽然可以直接从 Visual Studio
部署和运行，但这将绕过本示例将要演示的安装工具和过程。此示例的使用步骤如下所示：

1)  在 Visual Studio 中生成示例，而无需部署和执行它

2)  生成安装程序包的内容

3)  创建安装程序包

4)  安装程序包并运行示例

随着新 Project Scarlett 控制台的生成，将基于目标设备系列创建一个单独的
XVC 包。因此，在这里，不同的 .bat 和 .config 文件都有 XboxOne 和
Scarlett
版本，具体取决于你所测试的设备系列。无论使用何种设备系列，XPackage
代码在 GDK 中都保持不变。在 MicrosoftGame.config
文件中，将根据目标系列指定属性"TargetDeviceFamily=\"\[XboxOne/Scarlett\]\""。

本节将详细介绍每个步骤，以提供有关工具和过程的详细信息。第一步是简单地从
Visual Studio
构建示例。这将创建最终在创建包时使用的二进制文件和目录布局。生成示例后，通过命令行运行
CreateInstallPackage\_\[XboxOne/Scarlett\].bat。批处理文件将创建多个较大的文件作为内容文件，以便实时监视安装进度，并将正确的
MicrosoftGame.config 与目标设备系列集一起暂存。

一旦二进制文件和内容位于生成输出目录中，下一步是使用随 XDK 安装的
MakePkg 工具创建安装程序包。打开 Xbox 和 2017
游戏命令提示符，并导航到包含 StreamingInstall.vcxproj 的目录。
可从打开的命令提示符处运行 CreateXVC\_\[XboxOne/Scarlett\].bat
或直接运行命令：

XboxOne 设备系列：

> makepkg.exe pack /v /f Chunks_XboxOne.xml /d
> \".\\Gaming.Xbox.x64\\Layout\\Image\\Loose\" /pd
> \".\\Gaming.Xbox.x64\\Layout\\Image\"

Scarlett 设备系列：

> makepkg.exe pack /v /f Chunks_Scarlett.xml /d
> \".\\Gaming.Scarlett.x64\\Layout\\Image\\Loose\" /pd
> \".\\Gaming.Scarlett.x64\\Layout\\Image\"

此命令中使用的选项如下所示：

| 选 项 |  详细信息 |
|-----|----------------------------------------------------------------|
| /v  |  指定错误报告的详细输出。                                       |
| /f  |  指定要用于创建安装程序包的 布局文件。有关此示例中所含布局文件的详细信息，请参阅本部分中的 Chunks\_\[XboxOne/Scarlett\].xml。                             |
| /d  | 指定程序包内容的源目录。                                       |
| /pd | 指定安装程序包文件的输出目录。                                 |

由于程序包已填充了几个 GB
的填充内容，因此执行该包可能需要几分钟的时间。执行完后，将在 /pd
选项后指定的位置创建多个文件，本例为".\\Gaming.\[Xbox/Scarlett\].x64\\Layout\\Image"目录。将为实际安装程序包文件指定一个名称，该名称是程序包的包系列名称，而不是文件扩展名。

最后一步是将程序包安装到开发控制台上。有许多选项可用于确定要安装的内容，具体取决于要测试的场景。如果要测试流式安装的实现，可使用以下命令：

> xbapp install \[/l\] \[/w\] \<包名称\>

| 选项           |  详细信息                                            |
|----------------|-----------------------------------------------------|
| \<包名称\>     |  从 MakePkg 命令创建的安装程序包。                   |
| /l  |  指 定应仅安装启动区块。安装启动区块后，可运行游戏，但 仅可使用布局文件中标记为"启动"的区块中枚举的内容。  |
| /w  |  指定安装将使管道保持打开状态。 这可用于测试最初未安装的 OnDemand 和其他语言区块的动态安装。                          |
| \<完整包名称\>  |  安装在控制台上的游戏的名称。 这不应与包系列名称相混淆。可通过在命令提示符下运行 xbapp list 命令来获取控制台上已安装程序包的列表。   |

使用 /l 和 /w，你可以测试安装游戏的不同场景。如果只使用
/l，系统将仅安装初始区块。使用 /l 和
/w，系统将安装初始区块，并将在启动应用程序后安装其余区块。如果未指定任何标记，将安装整个基程序包，并去掉
OnDemand 和非默认语言区块。

某些区块是根据用户系统和语言自动安装的。例如，如果将 XboxOne
系列包部署到 Durango
控制台，并将语言设置为"en-US"，则不会安装标记了语言"fr"或设备"Xbox-Scorpio"的区块。对于
Scarlett 系列包，将基于目标设备（或开发工具包上的调试设置）安装 Lockhart
或 Anaconda 内容。

可使用 xdapp install
强制安装其他区块，其中包含一些可传递给命令的可选参数。

| 选项     |  详细信息                                                  |
|----------|-----------------------------------------------------------|
| /L anguages  |  指定将在 分号分隔的语言列表中安装的语言。在更改控制台设置后无需重 新运行安装命令，即可使用此选项测试多种语言的本地化内容。  |
| /Devices  |  指定应安装的特定于硬件的区块。这是要包含的不同硬件 SKU 的分号分隔列表。                                          |
| /A llChunks |  指定无论控制台硬件或设置如何，都应安装所有区块。 |

这不是可用于 xbapp install 命令的完整选项列表。请参阅 GDK
文档，了解完整的选项列表。

此示例使用以下控件：

| 操作                               |  游戏手柄控件                   |    |
|------------------------------------|--------------------------------|---|
| 导航网格菜单                       |  方向键                         |    |
| 从网格菜单选择一个项。 尝试安装缺失的区块（如果可以）。 如果有多个项处 于挂起状态，将首先安装当前网格项。 |  A  |  |
| 关闭打开的项并返回到网格菜单       |  B                              |    |
| 卸载所选的可选区块（如有可能）     |  X                              |    |
| 退出示例                           |  视图                           |    |
