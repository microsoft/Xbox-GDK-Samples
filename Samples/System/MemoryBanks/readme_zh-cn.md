# 内存存储示例

此示例与 Microsoft 游戏开发工具包预览版（2019 年 11 月）兼容

# 

# 说明

此示例演示了可用于管理内存存储的几种不同方法。

-   随机 -- 通过 VirtualAlloc 分配的基线内存存储。

-   固定 -- 演示如何以特定的内存地址分配内存。

-   只读 -- 演示如何将内存转换为只读。

-   存储切换 -- 演示如何创建可以旋转的内存存储链。

-   共享 -- 演示如何创建共享同一物理位置的多个内存存储。

# 构建示例

如果使用 Project Scarlett，你需要将 Gaming.Xbox.Scarlett.x64
平台配置添加到项目中。可以通过 Configuration Manager
执行此操作：选择"活动解决方案平台"下的"Configuration
Manager"选项，然后选择"新建..."。将"键入或选择新平台"设置为
Gaming.Xbox.Scarlett.x64，将"从此处复制设置"设置为
Gaming.Xbox.XboxOne.x64。然后选择"确定"。

有关详细信息，请参阅 GDK 文档中的"运行示例"。

# 实现说明

## 随机

此演示用作其他演示的基线。它使用 VirtualAlloc
分配内存存储，然后将磁盘中的二进制树读取到内存存储。需要修复磁盘中的数据。在内部，二进制树将索引存储到在其中分配的内存存储中。所有二进制树的内部指针都需要根据索引进行更新，因为程序运行之间基址会发生变化。

## 固定

此演示的工作原理与随机地址演示的方式相同。主要的区别在于，基址存储在数据文件中。这样，程序每次运行时，都可以在同一内存位置重新创建同一个存储。这意味着不需要内部索引，也不需要指针修复。从磁盘加载数据的速度要快得多，且
CPU 开销几乎为零。

## 存储切换

本演示展示了如何创建可交换其后备物理块的多个内存存储。这将交换两个物理内存块的虚拟地址。可以使用两个以上的内存存储，然后在两者之间轮换使用。此功能有多种用途：创建日志记录数据、用于保存重播的帧数据以及在缓冲区之间移动内存的其他位置。这样一来，就无需进行内存移动操作，并显著提升性能。

## 共享

本演示展示了如何创建均指向同一物理块的多个内存存储。如果彼此相邻创建了两个虚拟存储，这样就可以建立一个环形缓冲区，而不需要对边界副本进行多次内存复制操作。当数据被写到第一个虚拟存储的末端时，它将自动被包装到物理块的起始处。

另一个用途是创建多个具有不同权限的虚拟指针，例如，读-写和只读。但不允许混合调整缓存使用情况的权限。例如，写-合并、可缓存。

## 只读

这个演示展示了如何创建既是读写页面又是只读页面的页面。它使用共享演示执行此操作，其中一个存储被标记为读写，另一个存储被标记为只读。这种模式的一个主要用途是跟踪随机内存损坏。例如，标题使用的静态数据。文件加载系统可以使用读写地址来创建数据。标题的其余部分使用只读指针进行访问。如果有内存损坏问题，将在源中导致问题的确切位置引起异常。
