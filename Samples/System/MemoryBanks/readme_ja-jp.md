# メモリ バンクのサンプル

*このサンプルは、Microsoft ゲーム開発キットのプレビュー (2019 年 11 月)
に対応しています。*

# 

# 説明

このサンプルでは、メモリ
バンクの管理に使用できるさまざまな方法を示します。

-   ランダム - VirtualAlloc によって割り当てられたメモリ バンク。

-   固定 -- メモリを特定のメモリ アドレスに割り当てる方法を示します。

-   読み取り専用 -- メモリを読み取り専用に変換する方法を示します。

-   バンク スイッチング - 回転できるメモリ
    バンクのチェーンを作成する方法を示します。

-   共有 -- 同じ物理的な場所を共有する複数のメモリ
    バンクを作成する方法について説明します。

# サンプルの作成

Project Scarlett を使用している場合は、Gaming.Xbox.Scarlett.x64
プラットフォーム構成をプロジェクトに追加する必要があります。この操作は、*構成マネージャー*を使って行うことができます。\[アクティブなソリューション
プラットフォーム\] で \[構成マネージャー\] オプションを選択し、次に
\[新規作成\...\]
を選択します。\[新しいプラットフォームの入力または選択\] を
Gaming.Xbox.Scarlett.x64 に、\[設定のコピー元\]
をGaming.Xbox.XboxOne.x64 に設定します。次に \[OK\] を選択します。

*詳細については、GDK ドキュメントの*
「サンプルの実行」*を参照してください。*

# 実装に関する注意事項

## ランダム

このデモは、他のデモのベースラインとして機能します。VirtualAlloc
を使用してメモリ バンクを割り当て、ディスクからメモ バンクにバイナリ
ツリーが読み上げられます。ディスクからのデータは修正する必要があります。内部的には、バイナリ
ツリーはインデックスを自身が割り当てられたメモリ
バンク内に格納します。ベース
アドレスがプログラムの実行間で変更されるため、バイナリ
ツリーの内部ポインターはすべて、インデックスに基づいて更新する必要があります。

## 固定

このデモは、ランダム
アドレスのデモンストレーションと同じように動作します。主な違いは、ベース
アドレスがデータ
ファイルに格納されることです。そのため、プログラムを実行するたびに同じメモリ位置で同じバンクを再作成することができます。これは、内部インデックスが不要なことを意味し、ポインターの修正は不要です。CPU
のオーバーヘッドがほぼ 0
であれば、ディスクからデータを迅速に読み込むことができます。

## バンク スイッチング

このデモでは、バッキング物理ブロックを交換できる複数のメモリバンクを作成する方法について示します。これにより、2
つの物理メモリ ブロックの仮想アドレスが交換されます。2 つ以上のメモリ
バンクを使用している場合は、それらを切り替えることができます。この用途には、ログ
データ、再生の保存に使用するフレーム
データ、およびメモリをバッファー間で移動するその他の場所の作成などがあります。これにより、メモリ移動操作を削除できるため、パフォーマンスが大幅に向上します。

## 共有

このデモでは、すべてが同じ物理ブロックを指定する複数のメモリ
バンクを作成する方法を示します。2
つの仮想バンクが隣接して作成されている場合、この方法を使うと、複数のメモリを必要としないリング
バッファーは境界コピーに対して操作をコピーできます。最初の仮想バンクの最後に書き込まれたデータは、自動的に物理ブロックの先頭に一致します。

別の方法としては、読み取り/書き込みや読み取り専用など、アクセス許可の異なる複数の仮想ポインターを作成します。ただし、キャッシュ使用を調整するアクセス許可の組み合わせは許可されません。たとえば、書き込み連結やキャッシュ可能です。

## 読み取り専用

このデモでは、読み取り/書き込みおよび読み取り専用の両方のページを作成する方法を示します。1
つのバンクが読み取り/書き込みとマークされ、もう 1
つのバンクが読み取り専用としてマークされた共有デモを使用します。このパターンの主な用途は、ランダム
メモリの破損を追跡することです。たとえば、タイトルで使用される静的データなどです。ファイル読み込みシステムは、読み取り/書き込みアドレスを使用してデータを作成できます。タイトルの残りの部分では、読み取り専用ポインターを使用してアクセスします。メモリが破損した場合、問題の原因となっているソースの同じ場所で例外が発生します。
