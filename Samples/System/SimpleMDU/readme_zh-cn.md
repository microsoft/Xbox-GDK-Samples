# SimpleMDU 示例

# 说明

此示例演示内存解压缩单元 (MDU) 的基本属性。

如 GDK 文档中的*优化压缩内容*主题中所述，MDU 可用于通过 DirectStorage API 或内存中源解压缩数据流，作为 I/O 请求的一部分。 此示例生成一系列数据流，并使用两个 DirectStorage 队列从内存流和\\或存储流连续解压缩。 可以更改数据流的属性以观察 MDU 的吞吐量特征。

# 生成示例

此示例不支持 Xbox One 或桌面。 DirectStorage 仅在 Gaming.Xbox.Scarlett.x64 配置中受支持。

*有关详细信息，请参阅* *GDK 文档中的*__运行示例__。&nbsp;

# 使用示例

加载后，该示例将生成单个数据流，然后该数据流将持久保存到磁盘。 然后，内存中队列和存储队列都会使用该流。 然后，可以使用以下控件生成\\更改数据流：

| 向左\\向右方向键 | 调整较大数据流中每个单独压缩的&ldquo;区块&rdquo;的大小 |
|---|---|
| 向上\\向下方向键 | 调整数据流的压缩性 |
| LB\\RB | 调整数据流的内存对齐方式（16 字节或 4KiB） |
| Y | 启用\\禁用内存中解压缩 |
| B | 启用\\禁用从存储解压缩 |
| 查看 | 退出示例 |

# 实现说明

在 GDK 文档的*优化压缩内容*主题中，详细讨论了 MDU 解压缩选项。 MDU 支持两种不同的压缩策略（zlib 和 bcpack），这些策略可以单独应用或以系列方式应用于给定的数据流。

数据流通常细分为可卸载到 MDU 解压缩硬件的预确定大小，每个单独压缩的区块的大小上限为 32MiB。 如果使用 XBTC 进行纹理压缩，则这些单独压缩的流的大小由纹理导入时使用的选项决定。 如果单独压缩内容，则开发人员可以选择任何有效的&ldquo;区块&rdquo;大小，但使用较小或较大的大小需要考虑性能（有关更多详细信息，请参阅文档）。

根据内容和编码的类型，以及使用有损压缩还是无损压缩，典型的压缩比率可能会在
1.5:1 到 4:1 之间变化。 为了对此进行建模，在将示例下载的大小保持在最小范围内时，该示例会跨各种压缩范围生成数据，可通过控制器进行选择。 由于要实现一系列压缩比率而生成任意数据的性质，该示例仅使用 zlib 压缩策略，无需生成有效的 BC 编码纹理流。

选择流后，DSQueueHandler 的内部循环只是尝试向队列排积请求。 它尝试始终保留三批待处理的请求，每个批处理由 32MiB 的数据请求组成。 这样就可以根据游戏加载的典型数据轻松确定 MDU 吞吐量特征。

若要了解如何使用 BCPack 压缩的示例，请参阅 TextureCompression 示例。
