# SimpleMDU 샘플

# 설명

이 샘플은 MDU(메모리 압축 해제 장치)의 기본 속성을 보여줍니다.

GDK 문서의 *압축 콘텐츠 최적화* 항목에 설명된 대로 MDU는 DirectStorage API를 통해 또는 메모리 내 소스에서 I/O 요청의 일부로 데이터 스트림의 압축을 푸는 데 사용할 수 있습니다. 이 샘플은 일련의 데이터 스트림을 생성하고 두 개의 DirectStorage 큐를 사용하여 메모리 및\\또는 저장소의 스트림을 지속적으로 압축 해제합니다. 데이터 스트림의 속성을 변경하여 MDU의 처리량 특성을 관찰할 수 있습니다.

# 샘플 빌드

이 샘플은 Xbox One 또는 데스크톱을 지원하지 않습니다. DirectStorage는 Gaming.Xbox.Scarlett.x64 구성에서만 지원됩니다.

*GDK 설명서의* __샘플 실행__에서 *자세한 내용을 알아보세요.*

# 샘플 사용

로드 시 샘플은 디스크에 지속되는 단일 데이터 스트림을 생성합니다. 그런 다음 해당 스트림은 메모리 내 큐와 스토리지 큐에서 모두 사용됩니다. 그런 다음, 다음 컨트롤을 사용하여 데이터 스트림을 생성\\변경할 수 있습니다.

| 방향 패드 왼쪽\\오른쪽 | 더 큰 데이터 스트림 내에서 개별적으로 압축된 각 "청크"의 크기 조정 |
|---|---|
| 방향 패드 위\\아래 | 데이터 스트림의 압축률 조정 |
| 왼쪽 범퍼\\오른쪽 범퍼 | 데이터 스트림의 메모리 정렬 조정(16바이트 또는 4KiB) |
| 예 | 메모리 내 압축 해제 활성화\\비활성화 |
| B | 스토리지 압축 해제 활성화\\비활성화 |

# 구현 참고 사항

GDK 설명서의 *압축 콘텐츠 최적화* 항목 내에서 MDU 압축 해제 옵션에 대해 자세히 설명합니다. MDU는 주어진 데이터 스트림에 개별적으로 또는 직렬로 적용할 수 있는 두 가지 압축 전략(zlib 및 bcpack)을 지원합니다.

데이터 스트림은 일반적으로 MDU 압축 해제 하드웨어로 오프로드할 수 있는 미리 결정된 크기로 세분화되며, 크기 상한은 개별적으로 압축된 각 청크에 대해 32MiB입니다. 텍스처 압축에 XBTC를 사용하는 경우 이러한 개별적으로 압축된 스트림의 크기는 텍스처 가져오기 시 사용된 옵션에 따라 결정됩니다. 콘텐츠를 개별적으로 압축하는 경우 개발자는 유효한 "청크" 크기를 선택할 수 있지만 작거나 큰 크기를 사용할 때 성능 고려 사항이 있습니다(자세한 내용은 설명서 참조).

콘텐츠 및 인코딩 유형, 손실 압축 또는 비손실 압축 사용 여부에 따라 일반적인 압축 비율은
1.5:1에서 4:1까지 다양합니다. 이를 모델링하기 위해 샘플 다운로드 크기를 최소화하면서 샘플은 컨트롤러를 통해 선택할 수 있는 다양한 압축 범위에 걸쳐 데이터를 생성합니다. 압축 비율 범위를 달성하기 위한 임의 데이터 생성의 특성으로 인해 샘플은 유효한 BC 인코딩 텍스처 스트림을 생성할 필요가 없는 zlib 압축 전략만 사용합니다.

스트림이 선택되면 DSQueueHandler의 내부 루프는 단순히 요청으로 채워진 큐를 유지하려고 시도합니다. 32MiB의 데이터 요청으로 구성된 각 배치와 함께 항상 진행 중인 3개의 요청 배치를 유지하려고 시도합니다. 이를 통해 타이틀에 의해 로드된 일반적인 데이터를 기반으로 MDU 처리량 특성을 쉽게 결정할 수 있습니다.

BCPack 압축을 사용하는 방법에 대한 예제는 TextureCompression 샘플을 참조하세요.

zlib 라이브러리(버전 1.2.11)에는 다음 라이선스가 적용됩니다. <http://zlib.net/zlib_license.html>
