# 説明

このサンプルでは、CNG (Crypto: Next Generation) API を使用して DTLS 実装を使用して UDP トラフィックをセキュリティで保護するためのベスト プラクティスを示します。

# サンプルの実行

このサンプルを実行するには、含まれている DTLSEchoServer プロジェクトもビルドして実行する必要があります。 サーバーには、x509 証明書と RSA 秘密キーも必要です。

通常、運用タイトルではセキュリティ検証のためにセキュリティ キー サービスを使用して証明書情報を交換しますが、サンプルの目的では、これらの値をクライアントとサーバーの間でコピーまたは貼り付ける必要があります。

クライアントを起動すると、ID 文字列が生成され、表示されます。 この値は、サーバーを起動するために必要です。起動時にプロンプトが表示されます。 サーバーは ID 文字列も生成します。

クライアントで [接続を開く] を選択すると、サーバー アドレスと ID 文字列の入力を求められます。 これらの値を入力すると、クライアントはサーバーに接続するときにセキュリティのベスト プラクティスに従い、クライアントは任意のメッセージをサーバーに送信してエコーバックできます。

# 実装メモ

このサンプルでは、Microsoft CNG (Crypto: Next Generation) API を使用して、事前共有証明書と秘密キーを処理し、自己署名証明書を生成し、TLS_ECDHE_RSA_WITH_AES_256_CBC_SHA384 で DTLS を使用してセキュリティで保護された接続を実装する方法を示します。

基になる UDP ソケットは、Overlapped I/O と Windows スレッドプールを使用して、OS がデータを受信してからタイトルに配信されるまでの遅延を最小限に抑えています。

最後に、実稼働コードでは、キー サービスまたはロビー サービス (MPSD など) を使用して、ゲーム インスタンス間でキー マテリアルを安全に共有できるようにする必要があります。

# 既知の問題

このサンプルでは、DTLS 1.2 プロトコルの一部のみを実装し、実稼働対応の DTLS サーバーではなく、CNG API の使用のサンプルとして設計されています。 完全ではなく、堅牢ではなく、信頼性の高い UDP ネットワーク レイヤーではありません。
