# 説明

このサンプルでは、Linux サーバーで OpenSSL の DTLS 実装を使用して UDP トラフィックの保護をサポートするためのベスト プラクティスを示します。このサンプルは、ネットワーク セキュリティ OpenSSL サンプルのクライアントと組み合わせて動作するように設計されています。

# サンプルのビルド

サンプルの生成に使用された開発環境は次のとおりです。

- Windows 10 上の Linux 用 Windows サブシステム v2

- Ubuntu 20.04 LTS

- Visual Studio Code

ベース インストールとは別に、Ubuntu はさらに次のように構成されました。

`sudo apt install build-essential clang gcc gdb openssl-dev`

このサンプルには、.vscode ディレクトリに VS Code プロジェクト構成が含まれています。これは、ローカル システム構成に合わせて変更する必要がある場合があります。

プロジェクトは、上記の構成を前提として、次のようにビルドすることもできます。

`clang++ -std=c++17 -g ./\*.cpp -o ./NetworkSecurityOpenSSL_Linux -l ssl -l crypto -pthread`

# サンプルの実行

このサンプルを実行するには、ネットワーク セキュリティ OpenSSL サンプルもビルドして実行する必要があります。 サーバーには、x509 証明書と関連する秘密キーも必要です。

通常、運用タイトルではセキュリティ検証のためにセキュリティ キー サービスを使用して証明書情報を交換しますが、サンプルの目的では、これらの値をクライアントとサーバーの間でコピーまたは貼り付ける必要があります。

クライアントを起動すると、ID 文字列が生成され、表示されます。 この値は、サーバーを起動するために必要です。起動時にプロンプトが表示されます。 サーバーは ID 文字列も生成します。

クライアントで [接続を開く] を選択すると、サーバー アドレスと ID 文字列の入力を求められます。 これらの値を入力すると、クライアントはサーバーに接続するときにセキュリティのベスト プラクティスに従い、クライアントは任意のメッセージをサーバーに送信してエコーバックできます。

# 実装メモ

このサンプルの DTLS 実装は、Linux に移植されたネットワーク セキュリティ OpenSSL サンプルの実装と同じです。

クライアント バージョンとの違いは次のとおりです。

- Winsock API は汎用 BSD ソケットに置き換えられました

- Windows スレッド プールと重複した I/O が std::thread および select() ループに置き換えられました

このサンプルには、移植性のために STL 上に構築された XAsync および XTaskQueue の実装も含まれています。

最後に、実稼働コードでは、キー サービスまたはロビー サービス (MPSD など) を使用して、ゲーム インスタンス間でキー マテリアルを安全に共有できるようにする必要があります。
