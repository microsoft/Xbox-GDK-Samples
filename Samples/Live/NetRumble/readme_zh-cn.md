NetRumble 示例

此示例与 Microsoft 游戏开发工具包预览版（2019 年 11 月）兼容

# 说明

此示例演示了多人游戏功能如何使用 2015 Multiplayer API
打造完整的端到端游戏体验。 此示例当前仅支持 Gaming.Xbox.x64。

此示例提供了以下多人游戏方案选项。

-   创建可加入会话

> 创建一个大厅会话，该会话通过平台 UI 公布为可加入。
>
> 创建与大厅会话链接的游戏会话。

-   邀请好友和队员加入你的会话

> 打开系统 UI 邀请好友加入你的会话。使用自定义邀请字符串。
>
> 向队员发送邀请。

-   加入正在进行的好友会话

> 枚举并显示好友正在玩的会话，然后直接加入它们。也可以通过 Xbox 主机上的
> shell 或 Windows 上的 Xbox 应用（通过好友的玩家卡或活动源）或者 Party
> 应用（如果队员正在参加游戏会话）进行加入。

-   进行匹配

> 创建并注册一个匹配会话并提交匹配票证。成功后，匹配功能将返回一个游戏会话。

-   处理主机迁移**\
    **设置每种会话类型的主机，并在主机离开会话时迁移主机职责。

-   活动游戏

> 在所有会话成员之间发送和接收状态和游戏方案数据，一次最多可容纳 8
> 位玩家。在这种情况下，游戏有着令人惊叹的双向效果！

# 实现说明

此示例是一个展示游戏，演示了如何使用 Xbox Services API
multiplayer_manager 类实现 Xbox Live 多人游戏。

新的多人游戏 API 中淘汰了强制性 Xbox One
游戏队伍的概念。游戏可以自由地根据需要管理其会话，并公布希望可从 Xbox
One Shell 加入或看见哪些会话。请参阅示例中的
SetLobbySessionJoinRestrictionAsync、SetLobbySessionClosedAsync、*AdvertiseGameSessionAsync*
和 *GetGameTransferHandle*。

[注释：]{.underline} 在先前 XDK
上构建的利用游戏队伍的旧游戏仍受支持，但此示例中未显示。

此示例的匹配流程是一个非常简单的匹配实现，具有单个默认漏斗，并且不会回填空槽。有关更复杂的匹配方案的帮助，请参阅多人游戏
XDK 文档和《Multiplayer 2015 开发人员流程图》白皮书。

此示例使用新的 Multiplayer 2015 API *get_activities_for_social_group*
来呈现游戏中的可加入会话列表，该列表未包含在多人游戏管理器中。 可在
MultiplayerMenuScreen 中找到它。

在此示例中，将通过匹配会话模板进行自动评估，从而处理
QoS，你可以在随该示例提供的《服务配置》文档中参考该模板。 衡量的三个值为
BandwidthUp、BandwidthDown 和 LatencyAverage。

此示例实现的主机迁移设计比《Multiplayer 2015
开发人员流程图》中描述的内容更简单，因为成员列表槽 0
中的任何对象都将成为新主机。 有关更完整的基于 QoS
的解决方案，请参阅流程图。

# 已知问题

-   此示例提供的网络网格将用作你自己的实现的基线。[不应将网格视为有足够的适应性来供生产使用。]{.underline}

-   提供的网络[网格]{.underline}不适用于玩家采用严格 NAT
    类型的情况，或者主机迁移可能发生在严格主机上的情况。你的网格将需要处理这些情况。

-   此示例不考虑处理多个本地玩家的情况。希望混合本地和多人在线游戏的游戏需要缓存参与会话的本地玩家。

-   匹配会话模板中指定了 QoS 自动评估要求。游戏评估的 QoS
    当前不在此示例的范围内。

-   多人游戏管理器当前不查找过时的会话进行清理。在开发过程中，最佳做法是游戏查找并退出所有旧会话，例如，在启动多人游戏时，这些会话可能会因为较早的崩溃而徘徊不前。

-   CheckPrivilegeAsync 在适用于 UWP 的 Xbox Live SDK
    中不可用，因此运行该示例的 Windows
    版本时将跳过特权检查。预计将在未来的版本中提供。
