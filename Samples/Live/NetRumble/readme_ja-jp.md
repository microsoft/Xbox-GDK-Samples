NetRumble サンプル

*このサンプルは、Microsoft ゲーム開発キットのプレビュー (2019 年 11 月)
に対応しています。*

# 説明

このサンプルでは、2015 Multiplayer API
を使用したマルチプレイヤー機能で、完全なエンドツーエンドのゲーム
エクスペリエンスを構築する実例を示します。 このサンプルは、現在
Gaming.Xbox.x64 のみサポートしています。

このサンプルでは、次のマルチプレイヤー
シナリオのオプションが提供されます。

-   **参加可能セッションを作成する**

> プラットフォーム UI で参加可能と宣伝されるロビー
> セッションを作成する。
>
> ロビー セッションにリンクされたゲーム セッションを作成する。

-   **友達とパーティ メンバーをセッションに招待する**

> システム UI
> を開いて、友達をセッションに招待する。カスタムの招待状文字列を使用する。
>
> 招待をパーティ メンバーに送る。

-   **友達の進行中のセッションに参加する**

> 友達がプレイしているセッションを列挙および表示し、それらのセッションに直接参加する。参加は、Xbox
> コンソールのシェルから、または Windows の Xbox
> アプリから、友達のゲーマー カードまたはアクティビティ
> フィードを介して行うこともでき、またパーティー メンバーがゲーム
> セッションに参加している場合にはパーティ
> アプリから行うこともできます。

-   **マッチメイキング**

> マッチ セッションを作成および登録し、マッチメイキング
> チケットを送信する。成功した場合、マッチメイキングによってゲーム
> セッションが返されます。

-   **ホストの移行を処理する\
    **各タイプのセッションのホストを設定し、ホストがセッションから退出するときに、ホストの役割を移行します。

-   **アクティブなゲームプレイ**

> 一度に最大 8 名のプレーヤーの状態およびゲームプレイ
> シナリオのすべてのセッション
> メンバー間でデータを送受信します。この場合、ゲームプレイは、素晴らしいツインスティックのシューティングです。

Xbox One の devkit を使用している場合は、アクティブなソリューション
プラットフォームを Gaming.Xbox.XboxOne.x64 に設定します。

プラットフォームを Gaming.Xbox.Scarlett.x64 に設定します。

ドキュメント*の「サンプルの実行」を*参照してください*。

# 実装に関する注意事項

このサンプルは、Xbox サービス API の multiplayer_manager
クラスを使用して、Xbox Live のマルチプレイヤー
ゲームプレイを実装する方法を示す見本のゲームです。

必須の Xbox One ゲーム *パーティー*の概念は、新しいマルチプレイヤー API
の登場により廃止されました。タイトルで、セッションを適切な方法で自由に管理できます。また、これらのセッションのうち、参加可能であるもの、または
Xbox One
シェル内から表示できるものを自由にアドバタイズできます。サンプル内の
*SetLobbySessionJoinRestrictionAsync*、*SetLobbySessionClosedAsync*、*AdvertiseGameSessionAsync*、および
*GetGameTransferHandle* を参照してください。

*[注:]{.underline} ゲーム パーティを利用する以前の XDK
でビルドされたレガシー
タイトルは、サポートはされますが、このサンプルでは表示されません。*

このサンプルのマッチメイキング フローは、1
つの既定ホッパーを使用し、空きスロットを埋め戻さない非常にシンプルなマッチング実装です。より複雑なマッチメイキング
シナリオについてヘルプが必要な場合は、マルチプレイヤー XDK
に関するドキュメント、およびマルチプレイヤー 2015
開発者フローチャートに関するホワイトペーパーを参照してください。

このサンプルでは、新しいマルチプレイヤー 2015 API の
*get_activities_for_social_group* を使用して、ゲームで参加可能セッション
リストをレンダリングします。これは、マルチプレイヤー
マネージャーには含まれません。 それは、*MultiplayerMenuScreen*
で見つけることができます。

このサンプルでは、マッチ セッション テンプレートを介した自動評価によって
QoS
が処理されます。これについては、このサンプルとともに提供されるサービス構成に関するドキュメントで参照できます。
測定する 3 つの値は *BandwidthUp*、*BandwidthDown*、および
*LatencyAverage* です。

このサンプルは、メンバー リストのスロット 0
にいるメンバーは誰でも新しいホストになるという点でマルチプレイヤー 2015
開発者フローチャートで説明されているものよりもシンプルなホスト移行設計を実装しています。
より完全な QoS
ベースのソリューションについては、フローチャートを参照してください。

# 既知の問題

-   このサンプルで提供されているネットワーク
    メッシュは、独自の実装のベースラインとして使用できます。[このメッシュには、運用環境で使用可能な弾力性が十分にあるとは考えないでください。]{.underline}

-   提供されているネットワーク メッシュは、プレイヤーが固定的な NAT
    タイプを使用している場合や、固定的なホストに対してホストの移行が発生する場合のシナリオには対応していません。これらのケースは、ご使用のメッシュで処理を行う必要があります。

-   このサンプルでは、複数のローカル
    プレイヤーを処理するシナリオは考慮されていません。ローカルとオンラインの両方のマルチプレイヤーを混在させるタイトルでは、セッションに参加するローカル
    プレイヤーをキャッシュする必要があります。

-   QoS の要件を、自動評価用のマッチ セッション
    テンプレートで指定します。現在、タイトルが評価されている QoS
    はこのサンプルの対象範囲外です。

-   マルチプレイヤー
    マネージャーは、現時点ではクリーンアップする古いセッションを探しません。タイトルの開発中は、マルチプレイヤーを開始するとき、例えば以前発生したクラッシュが原因の古いセッションをすべて見つけて退出することをお勧めします。

-   *CheckPrivilegeAsync* は、UWP 用の Xbox Live SDK
    ではまだ使用できません。このため、このサンプルの Windows
    バージョンを実行すると、特権チェックがスキップされます。これは、将来のリリースで使用できるようになる予定です。
