# 説明

このサンプルでは、OpenSSL の DTLS 実装を使用して UDP トラフィックの保護をサポートするためのベスト プラクティスを示します。

# サンプルのビルド

このサンプルでは、Xbox One、Xbox Series 本体、GDK Desktop がサポートされています。 ビルドする構成をドロップダウンで選択します。

*詳細については、**GDK ドキュメント*の「__サンプルの実行__」を参照してください。

このサンプルには、OpenSSL のプリコンパイル済みバージョンは同梱されていません。 次のいずれかのソースから最新バージョンを取得し、プロジェクトに追加する必要があります。

PC の場合は、以下から最新のバイナリをダウンロードできます。

- <https://www.openssl.org/>

- <https://github.com/openssl/openssl>

別の方法として、[vcpkg](aka.ms/vcpkg) や nuget などのパッケージ マネージャーを使用します。

Xbox 本体の場合は、github からソースを取得し、次の構成でカスタム バージョンをビルドする必要があります。

```perl
perl&nbsp;Configure&nbsp;VC-WIN64A-masm&nbsp;no-ui-console&nbsp;no-dso&nbsp;no-stdio -D"WINAPI_FAMILY=WINAPI_FAMILY_GAMES"&nbsp;-D"_WIN32_WINNT=0x0A00" -DOPENSSL_SYS_WIN_CORE
```


# サンプルの実行

サンプルは、クライアントまたはホストとして実行でき、事前共有キーまたは証明書を使用できます。 このサンプルは、クライアントとホスト間の接続を一度に 1 つだけ示すように構築されています。 ホストとして開始するには、[接続を承諾] ボタンを押します。 事前共有キーまたは証明書のいずれかを使用する場合、サンプルは証明書のキーまたは指紋を出力します。 [承諾] をクリックすると、接続するクライアントの IP アドレスを求めるウィンドウがポップアップ表示されます。 本体では、これは、クライアントからのパケットを本体のファイアウォールを通して許可するために必要です。

![グラフィカル ユーザー インターフェイス、自動生成された説明](./media/image4.png)

ホストに接続するには、[接続を開く] ボタンをクリックします。 最初のポップアップ ウィンドウは、ホストの IP アドレスとポート用です。 2 つ目は、ホストが使用している指紋または事前共有キー用です。

接続が完了したら、[メッセージの送信] を押すと、2 つのサンプル インスタンス間で送信される文字列を入力できるようになります。 トラフィックが Wireshark などのツールで表示された場合、トラフィックは暗号化され、読み取り不可能になります。

# 実装メモ

このサンプルでは、DGRAM BIO ではなく OpenSSL のメモリ BIO を使用します。 これは、ソケットを複数の接続に再利用できるようにするために行われました (このサンプルでは示されていません)。 このデータを利用するには、ソケットと BIO の間でデータを移動する必要があり、DGRAM BIO の場合のように自動的には行われません。

基になる UDP ソケットは、Overlapped I/O と Windows スレッドプールを使用して、OS がデータを受信してからタイトルに配信されるまでの遅延を最小限に抑えています。

最後に、実稼働コードでは、キー サービスまたはロビー サービス (MPSD など) を使用して、ゲーム インスタンス間でキー マテリアルを安全に共有できるようにする必要があります。

# プライバシーにかんするせいめい

サンプルをコンパイルして実行する場合、サンプルの使用状況を追跡するために、サンプルの実行可能ファイルのファイル名が Microsoft に送信されます。 このデータ コレクションからオプトアウトするには、Main.cpp の "サンプル使用状況テレメトリ" というラベルの付いたコードのブロックを削除します。

Microsoft のプライバシー ポリシー全般の詳細については、「[Microsoft のプライバシーに関する声明](https://privacy.microsoft.com/en-us/privacystatement/)」を参照してください。
